AWS WAF는 CloudFront, ALB, API Gateway 같은 리소스로 들어오는 HTTP(S) 요청을 검사하는 관리형 웹 애플리케이션 방화벽입니다. web ACL에 규칙을 우선순위대로 쌓고, 요청마다 Allow · Block · Count · CAPTCHA · Challenge 중 하나로 처리합니다.

Why AWS WAF

포트가 아니라 요청 내용으로 판단해야 할 때

보안 그룹과 Network Firewall은 주소, 포트, 흐름을 봅니다. SQL injection, 자격 증명 대입, 스크래핑 봇은 정상 HTTPS 세션 안에서 일어나므로 헤더, 쿼리, 본문, 클라이언트 행위를 보는 L7 계층이 필요합니다.

Inline

서비스에 붙이는 방화벽

별도 어플라이언스나 라우팅 변경 없이, CloudFront 배포나 ALB 같은 리소스에 web ACL을 연결하면 바로 검사가 시작됩니다.

Managed

관리형 규칙으로 빠르게

AWS Managed Rules와 AWS Marketplace 규칙 그룹으로 흔한 웹 취약점, 평판 나쁜 IP, 봇을 먼저 막고 맞춤 규칙은 그 위에 더합니다.

Observe

Count로 먼저 관찰

규칙을 Count로 넣고 CloudWatch 지표, 샘플 요청, 전체 로그로 오탐을 확인한 뒤 Block으로 바꿉니다.

Rules · labels

규칙은 JSON 문장, 판단은 레이블로 이어 갑니다

아래는 로그인 경로에 대해 IP별 요청 수를 제한하되, 사내 IP 레이블이 붙은 요청은 빼는 rate-based rule입니다. 앞선 규칙이 붙인 레이블을 뒤 규칙의 조건으로 쓰면 규칙을 잘게 나눠 조합할 수 있습니다.

  1. 우선순위 순서 평가 Priority

    web ACL은 숫자가 낮은 규칙부터 평가합니다. Allow · Block 같은 종료 액션을 만나면 멈추고, 어디에도 맞지 않으면 web ACL의 기본 액션을 적용합니다.

  2. Count와 레이블 Label

    Count는 일치를 기록하고 다음 규칙으로 넘어가는 비종료 액션입니다. 규칙과 관리형 규칙 그룹이 붙인 레이블은 같은 web ACL 안에서 뒤 규칙이 LabelMatchStatement로 참조합니다.

  3. Rate-based rule 60–600s

    평가 창은 60 · 120 · 300 · 600초 중 고르고, 한도는 최소 10입니다. IP, forwarded IP, 헤더, 쿼리 인자, 레이블 네임스페이스 같은 키를 조합해 집계합니다. 정밀한 쿼터가 아니라 높은 요청률을 억제하는 용도입니다.

Features

주요 기능

Managed rules

AWS Managed Rules

Core rule set, Known bad inputs, SQL database, IP reputation 같은 규칙 그룹을 버전 단위로 씁니다. 그룹 안 개별 규칙의 액션을 override하거나 scope-down으로 적용 범위를 좁힙니다.

Bot Control

봇 식별과 관리

Common 수준은 스스로 신원을 밝히는 봇을 분류해 레이블을 붙이고, Targeted 수준은 브라우저 검증과 행위 분석으로 정체를 숨기는 봇까지 잡습니다. 검색 엔진처럼 유용한 봇은 검증 후 허용합니다.

Fraud Control

ATP · ACFP

ATP는 로그인 페이지의 자격 증명 대입과 계정 탈취 시도를, ACFP는 가입 페이지의 가짜 계정 생성을 탐지합니다. 유출 자격 증명 대조와 세션 단위 집계로 판정합니다.

CAPTCHA · Challenge

사람 · 브라우저 검증

CAPTCHA는 사용자에게 퍼즐을 풀게 하고, Challenge는 화면 없이 브라우저 환경을 검사합니다. 통과하면 AWS WAF 토큰이 발급되어 면제 시간 동안 다시 묻지 않습니다.

App integration

클라이언트 통합 SDK

JavaScript, iOS · Android SDK로 클라이언트가 미리 토큰을 받아 요청에 싣습니다. Bot Control Targeted와 Fraud Control의 효과를 제대로 내려면 SDK 통합을 권장합니다.

Logging

전체 요청 로그

web ACL 로그를 CloudWatch Logs, Amazon S3, Amazon Data Firehose로 보냅니다. 대상 이름은 aws-waf-logs-로 시작해야 하며, 필드 마스킹과 로그 필터로 양을 줄입니다.

L7 DDoS

Anti-DDoS 관리형 규칙 그룹

AWSManagedRulesAntiDDoSRuleSet은 리소스별 트래픽 기준선을 학습해 L7 DDoS를 수 초 안에 탐지합니다. 의심도가 낮은 요청은 silent Challenge로, 높은 요청은 Block으로 완화합니다. 유료 규칙 그룹입니다.

AI traffic

AI 봇 · 에이전트 관리

Bot Control이 AI 크롤러와 에이전트를 분류하고 AI activity 대시보드로 보여 줍니다. Web Bot Auth 서명으로 검증된 봇은 기본 허용되며, CloudFront에서는 AI traffic monetization으로 HTTP 402 기반 과금도 할 수 있습니다.

Request handling

레이블 전달과 정규화

dynamic label interpolation으로 레이블 네임스페이스, 클라이언트 IP, JA3 · JA4 지문을 맞춤 헤더나 응답 본문에 한 규칙으로 넣습니다. pre-parse text transformation은 파싱 전 쿼리 문자열을 정규화해 우회를 막습니다.

맞춤 응답: Block 액션에 상태 코드, 헤더, 본문을 지정해 사용자 정의 응답을 돌려주고, Allow · Count에서는 오리진으로 가는 요청에 맞춤 헤더를 넣을 수 있습니다.

Protected resources

web ACL을 연결하는 리소스

web ACL 하나를 같은 범위의 여러 리소스에 연결할 수 있지만, 리소스 하나에는 web ACL 하나만 연결됩니다. CloudFront용은 글로벌 범위로 만들고, 나머지는 리소스와 같은 리전에 만듭니다.

Reference architecture

엣지에서 먼저 거르고, 조직 전체에 같은 기준을 겁니다

웹 트래픽은 글로벌 web ACL이 연결된 CloudFront에서 먼저 검사합니다. 리전의 API Gateway에는 리전 web ACL을 둡니다. Firewall Manager는 조직의 모든 계정에 공통 규칙 그룹을 강제하고, 각 web ACL의 로그는 한 곳으로 모읍니다.

Getting started

첫 web ACL을 적용하는 순서

  1. STEP 1

    web ACL 생성

    보호할 리소스의 범위(CloudFront 또는 리전)를 고르고 기본 액션을 정합니다. 새 콘솔에서는 protection pack으로 표시됩니다.

  2. STEP 2

    관리형 규칙 추가

    Core rule set, IP reputation 등 AWS Managed Rules를 넣고 WCU 사용량을 확인합니다.

  3. STEP 3

    Count로 관찰

    규칙을 Count로 두고 로깅과 CloudWatch 지표를 켜서 오탐을 찾고 예외를 만듭니다.

  4. STEP 4

    Block 전환

    검증된 규칙부터 Block으로 바꾸고, rate-based rule과 Bot Control을 더합니다.

  5. STEP 5

    조직 확장

    Firewall Manager 정책으로 모든 계정과 새 리소스에 공통 규칙 그룹을 자동 적용합니다.

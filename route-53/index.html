모든 질의에 살아 있는 엔드포인트로 답하는 DNS

Route 53은 퍼블릭 도메인의 권한 DNS, VPC 안의 사설 DNS, 온프레미스와 주고받는 하이브리드 DNS를 하나의 서비스에서 운영합니다. 헬스 체크 결과를 응답에 반영해 장애가 난 엔드포인트로 트래픽이 가지 않게 합니다.

Why Route 53

DNS는 모든 연결의 첫 번째 홉입니다

이름 해석이 실패하면 네트워크가 정상이어도 서비스는 멈춥니다. 권한 DNS의 가용성, 응답에 반영되는 상태 정보, VPC와 온프레미스를 잇는 해석 경로를 함께 설계해야 합니다.

Available

가용성 중심 권한 DNS

호스팅 영역별 월간 가용성 100%를 SLA로 약정합니다. accelerated recovery를 켜면 us-east-1 장애 때도 1시간 안에 퍼블릭 레코드를 다시 바꿀 수 있습니다.

Aware

상태를 아는 응답

헬스 체크와 라우팅 정책을 묶어, 정상인 엔드포인트만 응답에 담습니다.

Hybrid

하나의 해석 경로

Resolver 엔드포인트와 규칙으로 VPC와 온프레미스 DNS가 서로의 도메인을 해석합니다.

Resolution scope

어디에서 묻는 질의를 누가 답하는가

같은 Route 53이라도 질의가 들어오는 위치에 따라 답하는 구성 요소가 다릅니다.

퍼블릭 호스팅 영역

인터넷의 재귀 리졸버가 묻는 질의에 권한 서버로 답합니다. 레코드마다 라우팅 정책과 헬스 체크를 붙일 수 있습니다.

Features

주요 기능

Health checks

헬스 체크

엔드포인트를 HTTP, HTTPS, TCP로 확인하거나, 다른 헬스 체크를 묶은 계산형 체크, CloudWatch 경보 기반 체크를 만듭니다. HTTP 응답 본문의 문자열 일치도 확인할 수 있습니다.

Hybrid DNS

Resolver 엔드포인트

VPC 서브넷에 ENI로 만들어지며 IP 주소가 최소 2개 필요합니다. 두 개 이상의 가용 영역에 두는 구성을 권장합니다. Inbound는 Do53, DoH, DoH-FIPS를, Outbound는 Do53과 DoH를 지원하며, 하위 도메인을 NS 레코드로 위임받는 delegation 엔드포인트도 만들 수 있습니다.

Forwarding

Resolver 규칙

도메인 단위로 질의를 어느 DNS 서버로 보낼지 정합니다. 전달 규칙 외에 하위 도메인을 사내 DNS로 넘기는 delegation 규칙도 있습니다. 규칙을 VPC에 연결하고, AWS RAM으로 다른 계정과 공유할 수 있습니다.

DNS security

DNS Firewall

VPC Resolver를 지나는 아웃바운드 질의를 도메인 목록으로 ALLOW, ALERT, BLOCK 합니다. DNS Firewall Advanced는 DNS 터널링과 DGA 도메인을 탐지하고, Palo Alto Networks Advanced DNS Security 규칙도 추가할 수 있습니다.

Multi-account

Route 53 Profiles

사설 호스팅 영역, Resolver 규칙, DNS Firewall 규칙 그룹, 인터페이스 VPC 엔드포인트, 질의 로깅 구성을 하나의 Profile로 묶어 여러 VPC와 계정에 적용합니다.

Anycast resolver

Route 53 Global Resolver

인증된 클라이언트가 위치와 무관하게 퍼블릭 도메인과 사설 호스팅 영역을 해석하는 인터넷 접근형 anycast 리졸버입니다. 2026년 3월 GA로 IPv4·IPv6 질의를 받고, 질의 필터링과 중앙 로깅을 함께 제공합니다.

Reference architecture

공유 서비스 VPC로 묶는 하이브리드 DNS

Resolver 엔드포인트를 공유 서비스 VPC에 두고, 규칙과 사설 호스팅 영역은 Profile로 워크로드 VPC에 배포합니다. 핵심은 질의 방향입니다. Inbound는 온프레미스 → AWS 방향으로 aws.corp.internal 질의를 받고, Outbound는 AWS → 온프레미스 방향으로 corp.internal 질의를 사내 DNS에 넘깁니다. Inbound로 들어온 질의는 엔드포인트가 있는 VPC 기준으로 해석되므로, 사설 호스팅 영역을 공유 서비스 VPC에도 연결해야 합니다.

Reference architecture · Global Resolver

어디서든 같은 anycast 주소로 묻는 Global Resolver

지점, 데이터센터, 원격 사용자가 VPN이나 Resolver 엔드포인트 없이 인터넷으로 같은 anycast IP 두 개에 질의합니다. 질의는 직접 고른 2개 이상의 리전 중 가장 가까운 곳에서 처리되고, 그 리전이 멈추면 다음으로 가까운 리전이 같은 주소로 받습니다. 각 리전은 클라이언트를 인증한 뒤 DNS view의 필터링 규칙을 적용하고, view에 연결된 사설 호스팅 영역이나 퍼블릭 DNS로 해석합니다.

Getting started

하이브리드 DNS를 여는 순서

  1. STEP 1

    보안 그룹 준비

    엔드포인트용 보안 그룹에 TCP·UDP 53을 허용합니다. DoH를 쓰면 443도 엽니다.

  2. STEP 2

    엔드포인트 생성

    공유 서비스 VPC에 Inbound와 Outbound 엔드포인트를 두 개 이상의 AZ에 만듭니다.

  3. STEP 3

    전달 규칙 작성

    corp.internal 같은 사내 도메인을 사내 DNS 서버 IP로 보내는 규칙을 Outbound 엔드포인트에 만듭니다.

  4. STEP 4

    VPC에 배포

    규칙과 사설 호스팅 영역을 Profile에 담아 워크로드 VPC에 연결하고, RAM으로 계정에 공유합니다.

  5. STEP 5

    사내 DNS 설정

    사내 DNS에 AWS 도메인을 Inbound 엔드포인트 IP로 보내는 조건부 전달을 넣고, 양방향으로 dig로 확인합니다.

Pricing

비용 항목

Route 53 비용은 호스팅 영역 수, 질의 수와 라우팅 정책 유형, 헬스 체크 수, Resolver 엔드포인트의 ENI 시간으로 정해집니다. 하이브리드 DNS에서는 엔드포인트 ENI 수가 고정비가 됩니다.

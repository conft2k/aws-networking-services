AWS Global Accelerator · 네트워크 계층 가속

고정 IP 두 개로, 가장 가까운 엣지에서 AWS 네트워크에 태웁니다

AWS Global Accelerator는 애플리케이션 앞에 고정 애니캐스트 IP를 둡니다. 사용자 트래픽은 가장 가까운 AWS 엣지 로케이션에서 AWS 글로벌 네트워크로 들어와, 상태가 정상인 리전 엔드포인트로 전달됩니다. TCP와 UDP 애플리케이션 모두에 씁니다.

Why Global Accelerator

입구는 고정하고, 경로와 엔드포인트는 AWS 안에서 바꿉니다

사용자가 멀리 있을수록 공용 인터넷 구간이 길어지고 품질이 흔들립니다. Global Accelerator는 사용자 가까운 곳에서 트래픽을 받아 AWS 네트워크로 옮기고, 리전이나 엔드포인트를 바꿔도 클라이언트가 보는 IP는 그대로 둡니다.

Static

바뀌지 않는 IP

가속기를 지울 때까지 IP가 유지됩니다. 방화벽 허용 목록이나 DNS 캐시 문제를 신경 쓰지 않고 뒤쪽 구성을 바꿀 수 있습니다.

Edge

가까운 엣지에서 진입

애니캐스트로 광고된 주소라 사용자와 가까운 엣지 로케이션에서 트래픽을 받고, 이후 구간은 AWS 글로벌 네트워크를 지납니다.

Healthy

상태 기반 라우팅

엔드포인트 상태를 계속 확인해 정상인 곳으로만 보냅니다. 비정상 엔드포인트는 1분 안에 감지해 서비스에서 뺍니다.

Traffic control

트래픽이 엔드포인트에 닿기까지

Standard 가속기는 리스너, 엔드포인트 그룹, 엔드포인트의 세 단계로 트래픽을 나눕니다. 위에서부터 차례로 적용됩니다.

Features

주요 기능

Failover

헬스 체크와 장애 조치

새 연결은 즉시 정상 엔드포인트로 갑니다. 기존 연결은 유휴 시간 제한(TCP 340초, UDP 30초)까지 원래 엔드포인트에 남습니다.

Source IP

클라이언트 IP 보존

ALB, EC2, 보안 그룹이 있는 NLB 엔드포인트가 원본 클라이언트 IP를 받습니다. ALB는 기본으로 켜져 있고, Elastic IP와 TLS 리스너를 쓰는 NLB에서는 쓸 수 없습니다. Custom routing 가속기는 항상 보존합니다.

Stateful apps

클라이언트 어피니티

원본 IP 기준으로 같은 사용자를 같은 엔드포인트에 연결합니다. 세션 상태를 서버에 두는 애플리케이션에 씁니다.

Dual stack

IPv6 지원

듀얼 스택 가속기는 IPv4 2개와 IPv6 2개, 모두 4개의 고정 주소를 받습니다. 엔드포인트는 클라이언트 IP 보존을 켠 ALB, 보안 그룹이 있는 NLB, EC2여야 하고 Elastic IP는 쓸 수 없습니다.

Your addresses

BYOIP

보유한 IPv4 주소 풀을 가져와 가속기의 고정 IP로 씁니다. 기존 허용 목록에 등록된 주소를 그대로 유지할 수 있습니다.

Protection

AWS Shield 연동

엣지에서 트래픽을 받기 때문에 AWS Shield의 DDoS 보호와 함께 동작합니다. 엔드포인트의 보안 그룹과 AWS WAF 규칙도 그대로 유지됩니다.

Accelerator types

트래픽 배분을 AWS에 맡길지, 애플리케이션이 목적지를 직접 정할지에 따라 고릅니다.

Reference architecture

사용자에서 리전 엔드포인트까지

서울과 미국의 사용자는 같은 고정 IP로 접속하지만, 각자 가까운 엣지 로케이션에서 들어옵니다. 엣지부터는 AWS 글로벌 네트워크를 지나 리전별 엔드포인트 그룹으로 전달되고, 트래픽 다이얼이 리전별 비율을 정합니다.

Getting started

가속기를 만드는 순서

  1. STEP 1

    가속기 생성

    Standard 또는 Custom routing을 고르고, IPv4나 듀얼 스택, 필요하면 BYOIP 주소를 정합니다.

  2. STEP 2

    리스너 추가

    프로토콜, 포트 범위, 클라이언트 어피니티를 정합니다.

  3. STEP 3

    엔드포인트 그룹

    리전마다 그룹을 만들고 트래픽 다이얼과 헬스 체크를 설정합니다.

  4. STEP 4

    엔드포인트 등록

    ALB, NLB, EC2, Elastic IP를 넣고 가중치와 클라이언트 IP 보존을 정합니다.

  5. STEP 5

    DNS 전환

    애플리케이션 도메인이 가속기의 고정 IP나 DNS 이름을 가리키도록 바꿉니다.

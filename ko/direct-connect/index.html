인터넷을 거치지 않고, 전용 회선으로 AWS에 연결하세요

온프레미스 데이터센터나 사무실을 AWS Direct Connect 로케이션에서 물리 회선으로 AWS 네트워크에 직접 연결합니다. 대역폭은 예측 가능하고, 지연은 일정하며, 트래픽은 공용 인터넷에 노출되지 않습니다.

Why Direct Connect

하이브리드 워크로드에는 예측 가능한 네트워크가 필요합니다

인터넷 VPN은 빠르게 시작하기 좋지만, 경로와 지연이 매번 달라집니다. 대용량 데이터 이전, 실시간 업무 시스템, 규제 대상 트래픽에는 품질이 보장되는 전용 경로가 맞습니다.

Consistent

일정한 성능

공용 인터넷 혼잡과 무관한 전용 대역폭으로, 지연과 처리량을 예측할 수 있습니다.

Private

사설 경로

트래픽이 AWS 글로벌 네트워크 안에서 이동합니다. MACsec과 IPsec으로 암호화를 더할 수 있습니다.

Cost

낮은 전송 비용

Direct Connect를 통한 아웃바운드 데이터 전송 요금은 인터넷 전송 요금보다 낮게 책정되어 있습니다.

Connection stack

하나의 회선, 세 개의 계층

Direct Connect는 물리 회선 위에 VLAN으로 가상 인터페이스를 나누고, 각 인터페이스에서 BGP로 경로를 교환합니다. 아래 물리 계층부터 위로 쌓입니다.

L3Routing

Features

주요 기능

Global reach

Direct Connect Gateway

하나의 연결로 여러 리전의 VPC와 Transit Gateway에 접근합니다. 리전마다 회선을 따로 둘 필요가 없습니다.

Hub & spoke

Transit Gateway 연동

Transit VIF와 DX Gateway로 Transit Gateway에 연결해 수많은 VPC를 한 지점에서 라우팅합니다.

Global WAN

Cloud WAN 연동

DX Gateway를 AWS Cloud WAN 코어 네트워크에 직접 연결하고, 세그먼트 정책으로 온프레미스 경로를 관리합니다.

Site to site

SiteLink

Direct Connect 로케이션 사이를 AWS 백본으로 직접 연결합니다. 리전을 거치지 않고 지사 간 트래픽을 주고받을 수 있습니다.

Encryption

MACsec · 사설 IP VPN

지원 로케이션의 전용 연결에서 IEEE 802.1AE MACsec을 쓰거나, Transit VIF 위에 사설 IP 기반 Site-to-Site VPN을 구성합니다.

Public services

Public VIF

Amazon S3 같은 AWS 공용 엔드포인트에 인터넷을 거치지 않고 접근합니다.

Reference architecture

온프레미스에서 VPC까지

고객 라우터는 Direct Connect 로케이션에서 AWS와 만납니다. DX Gateway가 VIF를 받아 여러 리전의 VPC와 Transit Gateway로 경로를 전달하고, Public VIF는 AWS 공용 서비스로 이어집니다.

Resiliency toolkit

업무 중요도에 맞춰 이중화하세요

Direct Connect 콘솔의 Resiliency Toolkit이 권장 구성에 맞춰 연결 주문을 안내합니다. SLA는 권장 구성을 따를 때 적용됩니다.

99.99%

최대 이중화 (Maximum Resiliency)

두 개 이상의 Direct Connect 로케이션에서 각각 별도 장비로 회선을 둡니다. 장비, 회선, 로케이션 장애를 모두 견디는 구성으로, 핵심 업무 워크로드에 권장합니다.

99.9%

높은 이중화 (High Resiliency)

두 개의 Direct Connect 로케이션에 회선을 하나씩 둡니다. 한 로케이션 전체 장애에도 연결이 유지됩니다.

Getting started

전용 연결을 여는 순서

  1. STEP 1

    연결 요청

    콘솔에서 로케이션과 포트 속도를 골라 연결을 요청합니다.

  2. STEP 2

    LOA-CFA 받기

    AWS가 포트를 할당하면 콘솔에서 LOA-CFA를 내려받습니다.

  3. STEP 3

    크로스커넥트

    LOA-CFA를 콜로케이션 사업자나 회선 파트너에 전달해 물리 연결을 완료합니다.

  4. STEP 4

    VIF 생성

    VLAN, BGP ASN, 피어 IP를 정하고 VIF를 만듭니다.

  5. STEP 5

    BGP 확인

    라우터에 BGP를 설정하고, 세션 상태와 VIF의 수신·광고 경로를 확인합니다.

Pricing · 기본 요금제

종량제(Pay-as-you-go): 쓴 만큼 냅니다

모든 연결에 기본으로 적용되는 요금제입니다. 포트를 쓰는 시간과 AWS에서 나가는 데이터 양으로 과금되고, 설치비와 최소 요금은 없습니다. 회선 파트너와 콜로케이션 비용은 따로 발생합니다. 10 · 100 Gbps 전용 연결은 다음 장의 정액제를 대신 고를 수 있습니다.

Pricing · 신규 요금제 (2026년 9월)

정액제(Flat-rate): 정해진 시간 요금에 DTO가 포함됩니다

10 · 100 Gbps 전용 연결에만 고를 수 있는 별도 요금제입니다. 대역폭과 Tier로 정해진 시간 요금만 내고, 선택한 Tier가 포함하는 리전에서 나가는 데이터(DTO)는 GB당 요금이 없습니다. 월 요금은 대역폭 · Tier별 시간 요금 × 연결이 프로비저닝된 시간이며, 1시간 단위로 올림해 과금합니다. 중국 리전을 뺀 모든 상용 리전의 Direct Connect 로케이션에서 쓸 수 있습니다.

정액제 Tier 구분
Tier범위트래픽을 보내는 리전과 로케이션의 관계예
Tier 1Local같은 메트로us-east-1 ↔ Ashburn(버지니아) 로케이션
Tier 2Regional같은 권역(대륙 등) 안us-east-1 ↔ San Francisco 로케이션
Tier 3Continental대륙 · 권역을 더 멀리 가로지름us-east-1 ↔ Cape Town 로케이션, eu-central-1 ↔ San Francisco
Tier 4Long-haul넓은 권역이나 다른 대륙—
Tier 5Global전 세계 모든 AWS 리전—

Tier는 연결마다 하나씩 고릅니다. 상위 Tier는 하위 Tier의 리전을 모두 포함하고, Tier 1이 가장 저렴합니다. 위 표는 AWS가 제시한 일반 기준이며, 경로별 정확한 Tier는 정액제 요금 페이지의 표로 확인합니다.

port-pair서로 다른 장비나 로케이션의 전용 연결 2개를 같은 대역폭 · Tier로 묶습니다. 한쪽은 대기용이라 10 Gbps port-pair의 사용 가능 대역폭은 20이 아니라 10 Gbps입니다. 기존 연결은 Resiliency Group에 넣어 port-pair로 만들 수 있고, 묶지 않고 개별 정액제 연결로 써도 됩니다.
여러 리전 연결DX Gateway, Transit Gateway, Cloud WAN을 붙이면 여러 리전의 트래픽이 들어올 수 있습니다. 붙이기 전에 Tier가 원하는 리전을 모두 포함하는지 확인하고, 새 리전으로 확장하면 Tier를 올려야 할 수 있습니다.
요금제 전환콘솔의 Change Billing Mode 또는 UpdateConnectionsBillingMode API로 언제든 바꿀 수 있고, 트래픽은 끊기지 않습니다. 같은 계정에서는 로케이션 단위로 적용되어, 연결 하나를 바꾸면 그 로케이션의 연결이 모두 바뀝니다.

Why Firewall Manager

계정이 늘어날수록 방화벽 설정은 흩어집니다

계정마다 web ACL, 보안 그룹, 방화벽 규칙을 따로 관리하면 누락과 예외가 쌓입니다. Firewall Manager는 보안 팀이 기준선을 정책으로 정의하고, 애플리케이션 팀은 그 위에 자기 규칙을 더하는 구조를 만듭니다.

Central

한 곳에서 정의, 전체에 배포

관리자 계정에서 정책을 만들면 범위 안의 모든 계정과 리소스에 같은 보호가 배포됩니다. 정책을 고치면 변경도 함께 전파됩니다.

Automatic

새 계정 · 새 리소스도 자동

조직에 계정이 들어오거나 범위에 맞는 리소스가 생기면 Firewall Manager가 평가해 바로 정책을 적용합니다.

Audit

위반을 찾고 보여 주기

정책별 규정 준수 대시보드로 위반 계정과 리소스, 그 이유를 확인합니다. 자동 수정 없이 보고만 받도록 시작할 수도 있습니다.

Prerequisites

정책을 만들기 전에 갖출 것

Firewall Manager는 조직 단위 서비스입니다. 아래 준비를 순서대로 마쳐야 콘솔에서 정책을 만들 수 있습니다.

  1. 01

    AWS Organizations 모든 기능 활성화

    관리 대상 계정이 하나의 조직에 속해야 하며, 통합 결제만이 아니라 all features가 켜져 있어야 합니다.

  2. 02

    기본 관리자 계정 지정

    관리 계정이 조직을 Firewall Manager에 온보딩하면서 default administrator를 지정합니다. 기본 관리자는 전체 범위를 갖고 서드파티 방화벽 정책도 관리합니다. 보통 별도 security 계정을 씁니다.

  3. 03

    AWS Config 활성화

    보호할 리소스가 있는 모든 멤버 계정과 리전에서 AWS Config를 켜야 합니다. Firewall Manager는 Config로 리소스 변경을 감지하고 규정 준수를 평가합니다.

  4. 04

    정책 유형별 추가 준비

    Network Firewall과 DNS Firewall 정책은 AWS RAM의 조직 리소스 공유가 필요하고, 서드파티 방화벽 정책은 AWS Marketplace 구독과 연동 설정이 필요합니다. 기본 비활성 리전은 따로 켜야 합니다.

Features

주요 기능

Policy scope

계정 · 리소스 · 태그로 범위 지정

조직 전체, 지정한 계정 · OU만, 또는 지정한 계정 · OU를 뺀 나머지에 적용합니다. 리소스는 유형을 고르고, 태그를 모두 가졌는지(AND) 하나라도 가졌는지(OR)로 포함 · 제외합니다. resource set으로 리소스를 직접 묶을 수도 있습니다.

Remediation

자동 수정과 보고만

위반 리소스를 자동으로 고치거나, 바꾸지 않고 보고만 받도록 고릅니다. 범위를 벗어난 리소스에서 보호를 떼고 Firewall Manager가 만든 리소스를 정리하는 옵션도 있습니다.

Compliance

정책별 규정 준수 대시보드

정책마다 범위 안 계정 수와 준수 계정 수를 보여 주고, 위반 계정 → 리소스 → 위반 이유까지 내려가 확인합니다. Amazon SNS 채널로 새 위반을 실시간 알림받습니다.

Security Hub

Security Hub CSPM findings

위반 리소스와 탐지된 공격을 findings로 Security Hub CSPM에 보냅니다. Firewall Manager를 쓰고 있으면 통합이 자동으로 켜지며, 다른 보안 서비스 결과와 함께 우선순위를 정합니다.

Managed lists

애플리케이션 · 프로토콜 목록

보안 그룹 정책에서 허용 · 금지할 포트와 프로토콜을 managed list로 정의해 재사용합니다. AWS가 제공하는 목록과 직접 만든 목록을 함께 씁니다.

Logging

WAF 로그 중앙 수집

AWS WAF 정책에 로깅을 켜면 범위 안 모든 계정의 web ACL 로그를 한 계정의 Amazon Data Firehose나 S3로 모읍니다. 민감한 필드는 정책에서 가립니다.

최근 업데이트: AWS WAF L7 Anti-DDoS 관리형 규칙 그룹을 정책에 추가 가능(2025년 6월), AWS PrivateLink 인터페이스 엔드포인트로 Firewall Manager API 호출(2025년 7월), Asia Pacific (Taipei) 리전(2025년 9월) · Asia Pacific (New Zealand) 리전(2026년 3월) 출시. AWS WAF 정책의 retrofit existing web ACLs로 애플리케이션 팀이 만든 web ACL을 그대로 두고 정책 규칙만 덧붙일 수 있습니다.

Network Firewall via FMS

Network Firewall 정책의 세 가지 관리 방식

Network Firewall 정책은 firewall management type에 따라 방화벽을 어디에 만들지 정합니다. 규칙 그룹은 관리자 계정에서 미리 만들어 두고, AWS RAM 조직 공유로 멤버 계정에 배포합니다.

  1. D

    분산형 · Distributed

    범위 안 계정의 VPC마다 방화벽을 만들고 AZ별 방화벽 서브넷에 엔드포인트를 둡니다. 라우팅은 Monitor 모드로 위반만 알리거나 Off로 둡니다.

  2. C

    중앙형 · Centralized

    지정한 계정의 검사 VPC 하나에 방화벽 하나를 만듭니다. Transit Gateway로 스포크 VPC 트래픽을 모아 검사하는 구조에 맞고, 라우팅은 직접 구성합니다.

  3. I

    기존 방화벽 가져오기 · Import

    이미 운영 중인 방화벽을 하나의 정책으로 가져와 관리하고, 조직 기준 규칙을 더해 표준을 맞춥니다.

규칙 평가 순서: 정책에서 stateful 규칙의 strict order 또는 action order를 고릅니다. Firewall Manager API의 StatefulEngineOptions.RuleOrder는 생략하면 DEFAULT_ACTION_ORDER로 문서화되어 있으니, Network Firewall 콘솔의 기본값인 strict order를 쓰려면 명시하세요.

Reference architecture

security 계정에서 정책을 내리고, 결과는 다시 모읍니다

관리 계정이 security 계정을 Firewall Manager 관리자로 지정합니다. 관리자는 정책을 만들어 OU별로 배포하고, 각 멤버 계정의 AWS Config가 변경을 감지하면 Firewall Manager가 규정 준수를 다시 평가합니다. 위반은 대시보드와 Security Hub CSPM에 모입니다.

Getting started

첫 정책을 적용하는 순서

  1. STEP 1

    조직과 관리자

    Organizations all features를 켜고, 관리 계정에서 security 계정을 기본 관리자로 지정합니다.

  2. STEP 2

    AWS Config 켜기

    보호할 리소스가 있는 모든 계정 · 리전에서 Config를 켭니다. 필요하면 RAM 조직 공유도 켭니다.

  3. STEP 3

    정책 작성

    정책 유형과 리전(CloudFront는 Global)을 고르고 규칙 그룹 · 기준 보안 그룹 등 내용을 채웁니다.

  4. STEP 4

    범위와 보고만

    계정 · OU, 리소스 유형, 태그로 범위를 정하고 자동 수정은 끈 채 위반 내역을 검토합니다.

  5. STEP 5

    자동 수정 전환

    영향을 확인한 뒤 자동 수정을 켜고, Security Hub CSPM과 SNS로 위반을 계속 추적합니다.

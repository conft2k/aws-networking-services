Why Network Manager

네트워크가 커질수록 "지금 어떤 상태인가"에 답하기 어려워집니다

리전마다 Transit Gateway가 있고, 계정마다 VPC가 붙고, 데이터센터와 지사가 VPN과 Direct Connect로 들어오면 상태 확인이 리전별 콘솔로 흩어집니다. Network Manager는 이 자원을 하나의 global network에 등록해 같은 화면과 같은 이벤트 스트림으로 봅니다.

See

한 곳에서 보는 토폴로지

등록한 Transit Gateway와 attachment, VPN, Connect peer, 온프레미스 사이트를 토폴로지 트리와 지도로 그립니다. 리전과 계정을 넘나들 필요가 없습니다.

Know

변경을 이벤트로 받기

토폴로지 변경, 경로 변경, 터널과 BGP 상태 변경을 EventBridge 이벤트로 받습니다. 알림과 자동 대응을 기존 이벤트 파이프라인에 붙입니다.

Verify

경로와 지연 시간 확인

Route Analyzer로 Transit Gateway 라우팅 테이블의 경로를 따라가고, Infrastructure Performance로 리전과 AZ 사이 AWS 네트워크 지연 시간을 확인합니다.

Global network objects

Global network를 이루는 구성 요소

global network는 네트워크 객체를 담는 최상위 컨테이너입니다. AWS 쪽은 Transit Gateway를 등록하거나 Cloud WAN 코어 네트워크를 만들어 채우고, 온프레미스 쪽은 site, device, link로 모델링합니다.

Global networkcontainer

하나의 사설 네트워크를 나타내는 최상위 객체입니다. Transit Gateway와 Cloud WAN 코어 네트워크를 함께 담을 수 있습니다.

Transit Gateway registrationAWS

여러 리전, 여러 계정의 Transit Gateway를 등록합니다. 등록한 뒤부터 토폴로지와 이벤트가 수집됩니다.

Core networkAWS

Cloud WAN으로 만드는 글로벌 코어 네트워크입니다. 정책, 세그먼트, attachment를 같은 콘솔에서 관리합니다.

Siteon-prem

지사, 사무실, 매장, 캠퍼스, 데이터센터 같은 물리적 장소입니다. 주소나 좌표를 넣으면 지도에 표시됩니다.

Deviceon-prem

사이트의 물리 또는 가상 장비입니다. 라우터, 방화벽, SD-WAN 장비, 다른 클라우드의 가상 어플라이언스도 포함합니다.

Linkon-prem

사이트의 인터넷 회선 하나입니다. 통신사, 회선 유형, 대역폭을 기록합니다.

Connectionon-prem

두 device 사이의 연결입니다. 온프레미스 장비끼리, 또는 온프레미스 장비와 VPC 안 가상 어플라이언스 사이를 표현합니다.

Associationmapping

Site-to-Site VPN의 customer gateway나 Transit Gateway Connect peer를 device(필요하면 link까지)에 연결해 AWS 자원과 온프레미스 객체를 잇습니다.

이름이 여럿이라 헷갈릴 수 있습니다. 콘솔 이름은 Network Manager이고, 그 안에서 Transit Gateway를 등록해 쓰는 부분을 문서에서는 AWS Global Networks for Transit Gateways, 코어 네트워크를 만드는 부분을 AWS Cloud WAN이라고 부릅니다. 둘 다 같은 global network 위에서 동작합니다.

Features

주요 기능

Topology

토폴로지 트리 · 지도

global network의 자원 관계를 트리와 토폴로지 그래프로 보여 줍니다. 사이트 위치는 Amazon Location Service 기반 지도에 표시됩니다.

Dashboard

Transit Gateway 네트워크 대시보드

등록한 Transit Gateway와 attachment의 트래픽, 패킷 drop 같은 CloudWatch 지표와 VPN 상태를 global network 단위로 모아 봅니다.

Events

EventBridge 이벤트

aws.networkmanager 소스로 Topology Change, Routing Update, Status Update 이벤트를 보냅니다. Cloud WAN을 쓰면 세그먼트와 정책 이벤트도 옵니다.

Route Analyzer

경로 분석

출발·도착 Transit Gateway attachment와 IP를 넣으면 라우팅 테이블을 따라 경로를 분석합니다. 리턴 경로와 VPC 안 middlebox 경유도 포함할 수 있습니다.

Performance

Infrastructure Performance

리전 간, AZ 간, AZ 내부의 AWS 네트워크 지연 시간을 거의 실시간과 과거 기간으로 보여 줍니다. CloudWatch 지표로 구독할 수 있습니다.

Multi-account

Organizations 연동

trusted access를 켜고 위임 관리자 계정을 등록하면 다른 멤버 계정의 Transit Gateway를 하나의 global network에 등록하고 모니터링합니다.

Ops questions

운영 질문별로 쓰는 기능

Network Manager는 데이터 경로에 들어가지 않습니다. 이미 있는 Transit Gateway와 Cloud WAN의 설정과 상태를 모아 보여 주는 관제 계층입니다. 질문에 따라 쓰는 기능과 보는 범위가 다릅니다.

운영 질문별 Network Manager 기능과 분석 범위
운영 질문쓰는 기능보는 범위한계 · 보완
무엇이 어디에 연결돼 있나? 토폴로지 트리 · 토폴로지 그래프 · 지도 등록한 Transit Gateway, attachment, VPN, Connect peer, site · device · link 온프레미스 객체는 직접 등록해야 지도에 나타납니다.
방금 무엇이 바뀌었나? 이벤트 (EventBridge) attachment 생성·삭제, 경로 추가·삭제, VPN 터널과 BGP 상태 변경 등록 전에 일어난 변경은 기록되지 않습니다. 전달은 best effort입니다.
A에서 B로 경로가 있나? Route Analyzer Transit Gateway 라우팅 테이블 (IPv4 · IPv6), 리턴 경로 VPC 라우팅 테이블, 보안 그룹, NACL은 보지 않습니다. Reachability Analyzer와 VPC Flow Logs로 보완합니다.
AWS 네트워크가 느린가? Infrastructure Performance 리전 간, AZ 간, AZ 내부의 AWS 백본 지연 시간 (p50) Transit Gateway, NAT gateway, ELB 같은 VPC 자원을 거치는 경로는 포함하지 않습니다. 저하 원인은 알려 주지 않습니다.
트래픽이 얼마나 흐르나? 대시보드 · CloudWatch 지표 Transit Gateway와 attachment의 bytes · packets · drop 흐름 단위 분석은 Transit Gateway Flow Logs를 씁니다.

Reference architecture

두 리전과 온프레미스를 묶은 global network

서울과 도쿄의 Transit Gateway를 global network에 등록하고, 데이터센터와 지사를 site로 모델링합니다. 토폴로지와 이벤트 데이터는 home region인 us-west-2로 모이고, 이벤트는 EventBridge를 거쳐 CloudWatch Logs와 알림으로 이어집니다.

Getting started

Global network를 여는 순서

  1. STEP 1

    Global network 생성

    Network Manager 콘솔에서 global network를 만듭니다. 데이터는 us-west-2에 모입니다.

  2. STEP 2

    멀티 계정 설정

    Organizations trusted access를 켜고 위임 관리자를 등록합니다. 필요한 역할은 StackSets로 배포됩니다.

  3. STEP 3

    Transit Gateway 등록

    리전과 계정의 Transit Gateway를 등록합니다. Cloud WAN을 쓰면 코어 네트워크를 만듭니다.

  4. STEP 4

    온프레미스 모델링

    site, device, link를 만들고 customer gateway와 Connect peer를 device에 연결합니다.

  5. STEP 5

    이벤트 · 지표 연결

    CloudWatch Logs Insights 온보딩을 하고 EventBridge 규칙과 지연 시간 구독을 설정합니다.

Pricing

비용 항목

Transit Gateway를 global network로 관리하는 기능에는 추가 요금이 없습니다. 비용은 관리 대상 네트워크 자원과, 이벤트와 지표를 보관하는 CloudWatch 같은 연계 서비스에서 생깁니다.

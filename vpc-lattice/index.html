Amazon VPC Lattice · 애플리케이션 네트워킹

VPC와 계정이 달라도 서비스 단위로 연결하고 통제하세요

Amazon VPC Lattice는 여러 VPC와 계정에 흩어진 서비스와 리소스를 하나의 service network로 묶습니다. 라우팅, 인증, 로깅을 서비스마다 정의하고, VPC 사이의 네트워크 연결은 직접 구성하지 않습니다.

Why VPC Lattice

VPC를 잇는 대신 서비스를 잇습니다

VPC 피어링이나 Transit Gateway로 서비스 간 통신을 열면 CIDR 설계, 라우팅 테이블, 보안 그룹 규칙이 VPC 수만큼 늘어납니다. VPC Lattice는 통신 단위를 서비스로 바꿔, 네트워크 팀과 애플리케이션 팀이 각자 맡은 부분만 관리하게 합니다.

Connect

겹치는 CIDR도 연결

VPC Lattice는 겹치는 CIDR을 지원합니다. 주소 체계를 다시 설계하지 않고 VPC와 계정 사이에서 서비스를 호출합니다.

Secure

요청 단위 인증

보안 그룹과 함께 IAM auth policy로 누가 어떤 서비스를 호출할 수 있는지 정합니다. 인증된 요청은 SigV4로 서명합니다.

Delegate

역할 분리

네트워크 관리자는 service network와 정책을, 서비스 소유자는 리스너와 대상 그룹을 관리합니다. AWS RAM으로 계정 간에 공유합니다.

Features

주요 기능

Routing

리스너 규칙

경로, 헤더, HTTP 메서드로 요청을 나눕니다. 여러 대상 그룹에 0–999 가중치로 보내 카나리 배포를 하거나, fixed-response로 404 · 500을 돌려줍니다.

Authorization

Auth policy

service network와 서비스에 각각 IAM 정책을 붙입니다. 인증 유형이 AWS_IAM이면 두 정책 모두 명시적으로 허용해야 요청이 통과합니다.

Multi-account

AWS RAM 공유

서비스, service network, resource configuration을 특정 계정, OU, 조직 전체와 공유합니다. 서비스 디렉터리에서 공유받은 서비스를 확인합니다.

TCP resources

Resource configuration

Amazon RDS 데이터베이스(ARN), 도메인 이름, 사설 IP, CIDR 범위를 다른 VPC와 계정에 TCP로 공개합니다. resource gateway가 리소스 VPC로 들어가는 입구입니다. 사용자 지정 도메인을 붙이면 소비자 VPC에 프라이빗 호스팅 영역이 자동으로 만들어지고, DNS 해석을 IN_VPC로 두면 사설 도메인 이름도 대상으로 쓸 수 있습니다.

Hybrid access

Service network endpoint

VPC에 service network 유형의 VPC 엔드포인트를 만들면 Direct Connect나 VPN으로 연결된 온프레미스에서도 서비스와 리소스에 접근합니다. 한 VPC를 여러 service network에 연결할 수도 있습니다.

Observability

Access logs

service network, 서비스, resource configuration 단위로 접근 로그를 켜고 CloudWatch Logs, Amazon S3, Amazon Data Firehose로 보냅니다.

Services vs resources

서비스와 resource configuration

HTTP 계열 애플리케이션은 서비스로, 데이터베이스처럼 TCP로 접근하는 리소스는 resource configuration으로 등록합니다.

Auth policy

IAM 정책으로 호출 권한을 정합니다

인증 유형을 AWS_IAM으로 두면 기본은 모두 거부입니다. 정책이 없으면 모든 요청이 access denied를 받습니다.

  1. service network 정책 확인

    auth policy가 켜져 있고 명시적 허용이 없으면 요청을 거부합니다.

  2. 서비스 정책 확인

    서비스에도 정책이 있으면 같은 방식으로 다시 평가합니다. 공통 규칙은 service network에, 더 좁은 규칙은 서비스에 둡니다.

  3. 호출자 IAM 정책 확인

    호출하는 역할의 자격 증명 기반 정책도 허용해야 합니다. 어느 정책이든 명시적 거부가 있으면 허용보다 우선합니다.

Reference architecture

여러 계정의 서비스와 데이터베이스를 하나의 네트워크로

클라이언트 VPC는 service network에 연결되고, 온프레미스는 service network endpoint를 거쳐 들어옵니다. 서비스와 데이터베이스는 각 소유 계정에 그대로 두고 AWS RAM으로 공유합니다.

Getting started

첫 서비스를 연결하는 순서

  1. STEP 1

    대상 그룹 생성

    대상 유형과 프로토콜, 헬스 체크를 정하고 대상을 등록합니다.

  2. STEP 2

    서비스와 리스너

    서비스를 만들고 리스너 프로토콜, 포트, 기본 규칙을 설정합니다.

  3. STEP 3

    Service network 생성

    인증 유형(NONE 또는 AWS_IAM)과 접근 로그 대상을 정합니다.

  4. STEP 4

    서비스 연결

    서비스를 service network에 연결합니다. 다른 계정 서비스는 RAM으로 공유받아 연결합니다.

  5. STEP 5

    VPC 연결과 정책

    클라이언트 VPC를 보안 그룹과 함께 연결하고, auth policy를 붙인 뒤 호출을 확인합니다.

Why Site-to-Site VPN

이미 있는 인터넷 회선으로 하이브리드 네트워크를 시작합니다

전용 회선을 준비하는 동안에도, 지사처럼 트래픽이 적은 거점에도 바로 쓸 수 있습니다. Direct Connect와 함께 쓰면 백업 경로가 되거나 전용 회선 위의 암호화 계층이 됩니다.

Ready

기존 장비로 연결

IPsec을 지원하는 라우터, 방화벽, 소프트웨어 어플라이언스를 고객 게이트웨이로 씁니다. 콘솔에서 장비별 설정 파일을 내려받을 수 있습니다.

HA

터널 이중화

연결마다 고가용성을 위한 터널 두 개가 제공됩니다. 두 터널을 모두 구성해 두면 한쪽 터널이 유지보수나 장애로 내려가도 연결이 유지됩니다.

Flexible

세 가지 종단 지점

VPC 하나에는 Virtual Private Gateway, 여러 VPC에는 Transit Gateway, 글로벌 네트워크에는 Cloud WAN으로 연결합니다.

Tunnel build-up

터널 하나가 올라오는 과정

각 터널은 IKE로 보안 연결을 만든 뒤 IPsec으로 트래픽을 감싸고, 터널 안쪽 주소로 경로를 교환합니다. 장애를 볼 때도 이 순서대로 확인합니다.

BGPRouting

터널 내부 주소와 경로 교환

터널마다 169.254.0.0/16 대역의 /30 내부 주소를 씁니다. Dynamic 연결은 이 주소로 BGP 세션을 맺고, Static 연결은 지정한 접두사만 전달합니다.

Routing

Static 또는 BGP

라우팅 방식은 연결을 만들 때 정합니다. 같은 경로가 Virtual Private Gateway에 Static과 BGP로 함께 있으면 Static 경로가 우선합니다.

Dynamic

BGP 라우팅

BGP를 지원하는 장비라면 이 방식을 권장합니다. 경로가 자동으로 오가고, 터널 장애 시 다른 터널로 경로가 넘어갑니다.

  • Transit Gateway에서 ECMP로 여러 터널 대역폭을 합칠 수 있습니다.
  • 고객 게이트웨이에서 받는 경로: VGW 100개, Transit Gateway 1,000개
Static

Static 라우팅

BGP를 지원하지 않는 장비에서 씁니다. 온프레미스 접두사를 연결에 직접 등록합니다.

  • ECMP는 지원하지 않습니다.
  • Cloud WAN 연결과 VPN Concentrator에서는 쓸 수 없습니다.
  • VGW 연결에 등록할 수 있는 Static 경로: 100개

Features

주요 기능

Acceleration

Accelerated VPN

AWS Global Accelerator로 고객 게이트웨이에서 가장 가까운 엣지 로케이션에 트래픽을 받아 AWS 글로벌 네트워크로 전달합니다. Transit Gateway 연결에서 사용하며(VGW 미지원), 연결을 만들 때만 켤 수 있습니다.

Over Direct Connect

Private IP VPN

Transit VIF와 DX Gateway 위에서 사설 IP로 IPsec 터널을 맺습니다. 공인 IP 없이 전용 회선 트래픽을 암호화합니다.

Bandwidth

Large Bandwidth Tunnel

Transit Gateway나 Cloud WAN 연결에서 터널당 최대 5 Gbps를 씁니다. 두 터널은 같은 대역폭으로 맞추며, Accelerated VPN과 함께 쓸 수 없습니다. 기존 연결도 터널 IP와 설정을 유지한 채 표준과 Large 사이에서 바꿀 수 있습니다.

Observability

터널 로그

IKE·IPsec·DPD 활동 로그와 BGP 상태·경로 변경 로그를 Amazon CloudWatch Logs로 보냅니다. 협상 실패 원인을 장비 로그 없이도 확인할 수 있습니다.

Dual stack

IPv6 터널

Transit Gateway와 Cloud WAN에서 외부 터널과 내부 트래픽을 IPv4, IPv6 조합으로 구성합니다. Virtual Private Gateway는 IPv4만 지원합니다.

Many sites

VPN Concentrator

최대 100 Mbps의 소규모 거점을 Concentrator 하나로 최대 100개까지 Transit Gateway에 연결합니다. Concentrator는 Transit Gateway 어태치먼트 하나로 보이며 총 5 Gbps를 거점들이 나눠 씁니다. BGP 라우팅만 지원합니다.

Termination

AWS 쪽 종단 지점 비교

연결할 네트워크 규모와 필요한 기능에 따라 VPN 연결을 붙일 곳을 고릅니다.

Reference architecture

인터넷 VPN과 Direct Connect 위 VPN

지사는 인터넷으로 두 터널을 Transit Gateway에 맺고 BGP로 경로를 교환합니다. 데이터센터는 Transit VIF와 DX Gateway를 거쳐 같은 Transit Gateway에 닿고, 그 위에 Private IP VPN으로 암호화를 더합니다.

Getting started

VPN 연결을 여는 순서

  1. STEP 1

    고객 게이트웨이

    온프레미스 장비의 공인 IP(또는 인증서)와 BGP ASN으로 Customer gateway를 만듭니다.

  2. STEP 2

    종단 지점 준비

    Virtual Private Gateway를 VPC에 붙이거나, Transit Gateway나 Cloud WAN을 준비합니다.

  3. STEP 3

    VPN 연결 생성

    라우팅 방식과 터널 옵션, 필요하면 가속과 터널 대역폭을 정합니다.

  4. STEP 4

    장비 설정

    장비 벤더에 맞는 설정 파일을 내려받아 두 터널을 모두 구성합니다.

  5. STEP 5

    라우팅 확인

    라우팅 테이블 전파를 켜고 터널 상태, BGP 세션, 수신 경로를 확인합니다.

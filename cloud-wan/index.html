AWS Cloud WAN · 글로벌 코어 네트워크

여러 리전의 네트워크를 정책 문서 하나로 운영하세요

AWS Cloud WAN은 리전, 세그먼트, 연결 규칙을 JSON 정책으로 선언하면 AWS가 각 리전에 코어 네트워크 엣지를 만들고 서로 메시로 연결합니다. 리전마다 Transit Gateway를 만들고 피어링 경로를 직접 관리하던 일을 정책 하나로 바꿉니다.

정책 구조 보기 아키텍처 보기
core-network-policy.jsonLIVE
{
  "version": "2025.11",
  "core-network-configuration": {
    "asn-ranges": ["64512-64555"],
    "edge-locations": [
      { "location": "ap-northeast-2" },
      { "location": "ap-northeast-1" },
      { "location": "us-east-1" }
    ]
  },
  "segments": [
    { "name": "prod",
      "require-attachment-acceptance": true },
    { "name": "shared" }
  ],
  "segment-actions": [{
    "action": "share",
    "mode": "attachment-route",
    "segment": "shared",
    "share-with": ["prod"]
  }]
}

세 리전에 코어 네트워크 엣지를 두고, prod와 shared 세그먼트를 만든 뒤 shared 경로를 prod에 공유합니다.

Why Cloud WAN

리전이 늘어도 라우팅 의도는 한 곳에 있어야 합니다

리전별 Transit Gateway와 피어링, 정적 경로로 글로벌 네트워크를 만들면 리전이 늘 때마다 설정이 흩어집니다. Cloud WAN은 원하는 상태를 선언하고, 변경 내용을 미리 확인한 뒤 적용합니다.

Declare

선언형 정책

세그먼트, 리전, 연결 매핑 규칙을 정책 버전으로 관리합니다. 적용 전에 변경 사항을 검토하고, 이전 버전으로 되돌릴 수 있습니다.

Segment

글로벌 세그먼트

세그먼트는 모든 리전에 걸친 라우팅 도메인입니다. 기본적으로 같은 세그먼트 안에서만 통신하며, MPLS의 VRF와 비슷하게 동작합니다.

Mesh

자동 리전 간 연결

정책에 리전을 추가하면 코어 네트워크 엣지가 생기고, 다른 엣지와 풀 메시로 연결됩니다. 리전 간 경로는 동적으로 전파됩니다.

Policy anatomy

코어 네트워크 정책의 구성 요소

정책 문서는 최상위 키 여덟 개로 이루어집니다. 앞의 세 개는 필수이고, 나머지는 필요한 만큼 더합니다.

versionrequired

정책 문법 버전입니다. Routing policy와 BGP 커뮤니티 전달을 쓰려면 2025.11을 지정합니다.

core-network-configurationrequired

ASN 범위, 엣지를 둘 리전(edge-locations), VPN ECMP · DNS · 보안 그룹 참조 지원 같은 전역 설정입니다.

segmentsrequired

라우팅 도메인을 정의합니다. 세그먼트별로 사용할 리전, 연결 승인 필요 여부, attachment 간 격리 여부를 정합니다.

network-function-groupsoptional

방화벽이나 IDS/IPS를 호스팅하는 attachment 묶음입니다. 서비스 삽입의 대상이 됩니다.

segment-actionsoptional

세그먼트 사이의 경로 공유, 정적 경로, 서비스 삽입, Routing policy 연결을 정의합니다.

attachment-policiesoptional

태그 같은 조건으로 attachment를 세그먼트나 network function group에 자동으로 매핑합니다.

routing-policiesoptional

inbound 또는 outbound 방향의 경로 필터, 요약, BGP 속성 변경 규칙입니다.

attachment-routing-policy-rulesoptional

Routing policy 레이블 조건에 맞는 attachment에 어떤 Routing policy를 적용할지 정합니다.

segment-actions의 action 값 sharecreate-routesend-viasend-toassociate-routing-policy

Features

주요 기능

Auto mapping

Attachment 정책

attachment에 붙은 태그를 보고 세그먼트를 자동으로 정합니다. 승인이 필요한 세그먼트는 네트워크 팀이 확인한 뒤 연결합니다.

Service insertion

Network function group

send-via로 세그먼트 간 트래픽을, send-to로 인터넷이나 온프레미스로 나가는 트래픽을 검사 VPC로 보냅니다. send-via는 single-hop과 dual-hop 중에서 고릅니다.

Hybrid

Direct Connect gateway 연결

DX gateway를 코어 네트워크에 직접 붙입니다. 중간 Transit Gateway 없이 Transit VIF로 받은 온프레미스 경로가 세그먼트 전체 리전에 전파됩니다.

Route control

Routing policy

prefix, prefix list, AS-PATH, BGP 커뮤니티, MED로 경로를 골라 필터링하거나 요약하고, Local Preference · AS-PATH · MED로 경로 선호를 조정합니다. attachment뿐 아니라 세그먼트 공유와 리전 간 경로에도 적용합니다.

SD-WAN

Tunnel-less Connect

VPC 안의 SD-WAN 장비가 GRE 터널 없이 코어 네트워크 엣지와 BGP를 맺습니다. Connect 피어당 AZ별 최대 100 Gbps입니다.

Migration

Transit Gateway 피어링

기존 Transit Gateway를 같은 리전의 코어 네트워크 엣지와 피어링하고, Transit Gateway 라우팅 테이블을 세그먼트에 연결해 단계적으로 옮깁니다.

Attachment types

연결 유형별 대역폭과 Routing policy 지원

VPC는 inbound 경로 필터링만 지원하고, BGP 기반 연결은 요약과 BGP 속성 변경까지 지원합니다. Routing policy는 network function group에는 적용되지 않습니다.

Reference architecture

세 리전에 걸친 코어 네트워크

코어 네트워크 엣지 세 개가 풀 메시로 연결됩니다. 각 attachment는 태그에 따라 세그먼트에 들어가고, 세그먼트 간 트래픽은 network function group의 검사 VPC를 거칩니다.

Getting started

코어 네트워크를 여는 순서

  1. STEP 1

    Global network 생성

    Network Manager에서 코어 네트워크를 담을 global network를 만듭니다.

  2. STEP 2

    정책 작성

    ASN 범위, 엣지 리전, 세그먼트, attachment 정책을 정의합니다.

  3. STEP 3

    변경 사항 검토 · 적용

    정책 버전의 change set을 확인하고 실행해 엣지를 배포합니다.

  4. STEP 4

    Attachment 연결

    VPC, VPN, Connect, DX gateway를 태그와 함께 연결하고, 필요하면 승인합니다.

  5. STEP 5

    경로 확인

    세그먼트별 라우팅 테이블에서 리전 간 경로와 공유 경로를 확인합니다.

Pricing

비용 항목

Cloud WAN 요금은 코어 네트워크 엣지 수, attachment 수와 시간, 그리고 코어 네트워크로 보낸 데이터 양으로 정해집니다. 리전 간 전송과 VPN, Direct Connect 회선 요금은 따로 붙습니다.

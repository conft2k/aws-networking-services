Why Reachability Analyzer

"왜 안 붙지?"에 구성 근거로 답합니다

연결 문제는 라우팅 테이블, 보안 그룹, NACL, 로드 밸런서, TGW 라우팅이 겹친 곳에서 생깁니다. 콘솔을 하나씩 열어 보는 대신 경로 하나를 정의하고 분석을 실행합니다.

Static

패킷을 보내지 않는 진단

구성만으로 판정하므로 아직 워크로드가 없는 환경이나 운영 중인 환경 모두 영향 없이 검사합니다. 반대로 일시적인 장애나 패킷 손실은 대상이 아닙니다.

Explain

막힌 구성요소와 이유

도달하지 않으면 차단한 구성요소 또는 조합과 explanation code를 돌려줍니다. 도달하면 지나가는 구성요소를 순서대로 보여줍니다.

Verify

변경 전후 검증

API로 분석을 실행할 수 있어 배포 파이프라인에서 의도한 경로가 열리고 닫혔는지 확인하는 단계로 씁니다.

How analysis works

경로를 정의하고, 구성 모델로 판정합니다

경로(path)는 출발지, 목적지, 프로토콜, 목적지 포트로 이루어집니다. 분석(analysis)을 실행하면 결과에 도달 여부, 정방향 · 반환 경로 구성요소, 차단 이유가 담깁니다. 아래는 결과를 줄인 예시입니다.

  1. 최단 경로를 보여줌 reachable

    도달 가능한 경로가 여럿이면 가장 짧은 경로를 표시합니다. 특정 중간 구성요소를 포함하거나 제외해 다시 분석하면 다른 경로를 확인할 수 있습니다.

  2. 차단 이유를 코드로 not reachable

    CANNOT_ROUTE, ENI_SG_RULES_MISMATCH, FIREWALL_RULES_RESTRICTION처럼 원인 유형을 코드로 알려줍니다. 막는 구성요소가 더 있을 수 있으니 고친 뒤 다시 분석합니다.

  3. 패킷 헤더 변환 반영

    IGW와 NAT 게이트웨이의 주소 변환처럼 중간 구성요소가 헤더를 바꾸면, 출발지를 떠난 헤더와 목적지에 도착한 헤더를 각각 보여줍니다.

Features

주요 기능

Endpoints

출발지 · 목적지 유형

EC2 인스턴스, 네트워크 인터페이스, IGW, Transit Gateway와 attachment, Virtual private gateway, VPC 엔드포인트와 엔드포인트 서비스, VPC peering을 지정합니다. 목적지로는 IP 주소도 됩니다.

Evaluated

평가하는 구성요소

라우팅 테이블, 보안 그룹, NACL, prefix list, 로드 밸런서와 대상 그룹, NAT 게이트웨이, TGW 라우팅 테이블, VPN 연결, gateway endpoint를 경로 위에서 함께 평가합니다.

Network Firewall

방화벽 규칙까지

Network Firewall의 stateless · stateful 5-tuple 규칙을 모두 평가합니다. 도메인 목록, Suricata 규칙, rule option, 태그 기반 리소스 그룹 같은 미지원 규칙을 만나면 경로 상세에 안내 메시지를 남깁니다. 리소스 그룹을 참조하는 rule group이 있으면 분석이 실패합니다.

Filters

중간 구성요소 지정 · 제외

로드 밸런서, NAT 게이트웨이, Network Firewall, Transit Gateway, peering을 반드시 지나거나 피하도록 분석을 좁혀 원하는 경로를 검증합니다.

Cross-account

조직 단위 교차 계정 분석

Organizations trusted access를 켜면 관리 계정이나 delegated administrator 계정에서 다른 멤버 계정의 리소스를 출발지 · 목적지로 지정합니다.

Automation

API · CLI로 반복 검증

CreateNetworkInsightsPath와 StartNetworkInsightsAnalysis로 경로를 저장해 두고, 변경할 때마다 같은 경로를 다시 분석합니다.

분석은 IPv4만 대상으로 합니다. 같은 리전 안에서, 같은 VPC이거나 peering 또는 Transit Gateway로 연결된 VPC 사이 경로를 분석합니다. TGW Connect attachment와 TGW policy table, 대상 상태(health), BYOIP 광고 상태, Traffic Mirroring은 고려하지 않습니다. TGW 라우팅 테이블을 지나는 TCP 경로는 정방향만 분석하고, GWLB 엔드포인트를 지나는 경로에는 GWLB와 그 대상이 포함되지 않습니다.

Reachability vs Network Access

한 경로를 진단할지, 전체 접근을 감사할지

두 도구 모두 automated reasoning 기반의 정적 분석입니다. Reachability Analyzer는 "A에서 B로 갈 수 있나"를 묻고, Network Access Analyzer는 Network Access Scope로 정의한 "있어서는 안 되는 경로"를 찾습니다.

Reference architecture

조직 안의 여러 계정을 가로지르는 경로 분석

delegated administrator 계정에서 계정 A의 인스턴스를 출발지로, 계정 B의 인스턴스를 목적지로 지정합니다. 분석은 네트워크 계정의 Transit Gateway 라우팅까지 따라가고, 계정 B 보안 그룹에서 막힌 지점을 보고합니다. VPC 구성은 VPC, 허브 라우팅은 Transit Gateway 페이지를 참고하세요.

관리 계정은 조직 내 모든 계정의 리소스를, delegated administrator 계정은 관리 계정을 제외한 멤버 계정과 명시적으로 공유받은 관리 계정 리소스를 분석합니다. 실제 트래픽 흐름은 VPC Flow Logs로, 글로벌 토폴로지와 경로 모니터링은 Network Manager로 보완합니다.

Getting started

시작하기

  1. STEP 1

    경로 정의

    출발지와 목적지 리소스, 프로토콜(TCP · UDP), 목적지 포트를 지정합니다. 필요하면 출발지 · 목적지 주소와 포트 범위 필터를 더합니다.

  2. STEP 2

    분석 실행

    경로를 저장하고 분석을 시작합니다. 특정 중간 구성요소를 지나야 하거나 피해야 하면 이때 지정합니다.

  3. STEP 3

    결과 읽기

    도달하면 hop-by-hop 경로를, 막히면 explanation code와 차단 구성요소를 확인합니다.

  4. STEP 4

    수정 후 재분석

    라우팅이나 보안 그룹을 고친 뒤 같은 경로를 다시 분석합니다. 차단 요소가 더 있으면 이어서 나타납니다.

  5. STEP 5

    확장과 자동화

    교차 계정이 필요하면 trusted access와 delegated administrator를 설정하고, 주요 경로는 변경 파이프라인에서 API로 재검증합니다.

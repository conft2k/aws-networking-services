Elastic Load Balancing · ALB · NLB · GWLB

트래픽의 계층에 맞는 로드 밸런서를 고르세요

Elastic Load Balancing은 들어오는 트래픽을 여러 가용 영역의 정상 대상으로 나눕니다. HTTP 요청은 Application Load Balancer가, TCP · UDP 연결은 Network Load Balancer가, 보안 어플라이언스로 보낼 IP 패킷은 Gateway Load Balancer가 맡습니다.

Why Elastic Load Balancing

대상이 늘고 줄어도 진입점은 하나로 유지됩니다

로드 밸런서는 대상의 상태를 계속 확인하고, 정상인 대상에만 트래픽을 보냅니다. Auto Scaling 그룹이나 컨테이너가 바뀌어도 클라이언트가 쓰는 주소는 그대로입니다.

Available

가용 영역 분산

여러 가용 영역에 노드를 두고, 헬스 체크를 통과한 대상에만 요청을 보냅니다.

Scale

트래픽에 따른 확장

로드 밸런서 용량은 트래픽에 맞춰 자동으로 늘어납니다. Network Load Balancer는 초당 수백만 건의 요청을 처리합니다.

Secure

TLS와 인증을 앞단에서

ACM 인증서로 TLS를 종료하고, ALB에서는 mTLS, OIDC · Amazon Cognito 인증, JWT 검증까지 처리합니다.

Listener rules

ALB는 요청 내용을 보고 경로를 정합니다

리스너 규칙은 우선순위가 낮은 번호부터 평가하고, 처음 일치한 규칙의 액션을 실행합니다. 조건은 host-header, path-pattern, http-header, http-request-method, query-string, source-ip 여섯 가지입니다.

규칙마다 forward, redirect, fixed-response 중 하나의 라우팅 액션이 마지막에 있어야 합니다. HTTPS 리스너에서는 authenticate-cognito, authenticate-oidc, jwt-validation 액션을 그 앞에 둘 수 있습니다.

Features

주요 기능

ALB · Authentication

인증 액션

Amazon Cognito나 OIDC 호환 IdP로 사용자를 인증하거나, 요청의 JWT 액세스 토큰을 검증한 뒤 대상으로 보냅니다.

ALB · mTLS

상호 TLS 인증

verify 모드는 트러스트 스토어의 CA로 클라이언트 인증서를 검증합니다. passthrough 모드는 인증서 체인을 대상에 그대로 넘깁니다.

TLS

TLS 종료와 보안 정책

ALB HTTPS 리스너와 NLB TLS 리스너에 인증서를 두고, 보안 정책으로 프로토콜과 암호 스위트를 정합니다. NLB는 ALPN 정책도 지원합니다.

NLB · Static IP

고정 IP와 Elastic IP

NLB 노드는 가용 영역마다 고정 IP를 가집니다. 인터넷 연결 NLB는 서브넷마다 Elastic IP 하나를 붙일 수 있고, ALB를 대상으로 등록해 ALB 앞에 고정 IP를 둘 수 있습니다.

NLB · Source IP

클라이언트 IP 보존

대상이 원래 클라이언트 IP를 그대로 받습니다. instance 대상은 기본으로 켜져 있고, UDP · QUIC 대상 그룹에서는 끌 수 없습니다.

GWLB · Inspection

Gateway Load Balancer endpoint

VPC 라우팅 테이블에서 GWLB endpoint를 다음 홉으로 지정하면, 트래픽이 PrivateLink로 보안 VPC의 어플라이언스를 거쳐 돌아옵니다.

Reference architecture

인바운드 검사 뒤 ALB로 분산

인터넷 게이트웨이의 엣지 라우팅 테이블이 ALB 서브넷으로 가는 트래픽을 GWLB endpoint로 보냅니다. GWLB는 GENEVE로 감싼 패킷을 어플라이언스에 나누고, 검사를 통과한 트래픽은 ALB를 거쳐 대상에 도착합니다.

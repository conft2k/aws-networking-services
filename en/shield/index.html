Stop DDoS at the edge, with an expert team for large attacks

With a Shield Advanced subscription, the resources you designate also get automatic L7 mitigation, Shield Response Team support, and cost protection.

Why Shield

Borrow AWS scale instead of building your own DDoS defense

DDoS attacks saturate bandwidth (L3), exhaust connection state (L4), or flood you with legitimate-looking requests (L7). Shield detects and mitigates this traffic on the AWS edge and Regional infrastructure.

Always on

Always-on detection and inline mitigation

With no configuration, Shield Standard automatically mitigates common L3 · L4 attacks such as SYN floods, UDP floods, and reflection attacks.

App aware

Application-aware detection

Shield Advanced combines each protected resource's traffic baseline with Route 53 health checks to catch smaller attacks, faster.

Experts

Humans in the loop

During an attack, the Shield Response Team analyzes AWS WAF logs and writes custom rules, then provides post-attack analysis and architecture recommendations.

Standard vs Advanced

Shield Standard and Shield Advanced

Shield Standard applies automatically to every AWS customer. Shield Advanced is subscribed per account and only takes effect on resources you explicitly add protection to.

Shield Advanced features

Shield Advanced key features

L7 DDoS

Anti-DDoS managed rule group

L7 protection is moving to the AWS WAF AWSManagedRulesAntiDDoSRuleSet (50 WCU). It establishes a baseline within minutes without health checks, and you set Block and Challenge sensitivity separately. Legacy automatic L7 mitigation (150 WCU) is migrated automatically starting October 25, 2026, and support ends on January 29, 2027.

Health-based

Health-based detection

Associate a Route 53 health check with a protection, and when the health check is unhealthy, Shield detects and mitigates faster at lower thresholds. Use it with every resource type except Route 53 hosted zones.

SRT

Shield Response Team

Grant an IAM role that trusts drt.shield.amazonaws.com, and the SRT reviews WAF logs and creates or updates web ACL rules on your behalf. It acts only with your explicit authorization.

Proactive engagement

Proactive engagement

If an associated health check becomes unhealthy during a detected event, the SRT contacts your registered contacts first. Associated health checks are a prerequisite.

Protection groups

Protection groups

Group multiple protected resources into one unit for combined detection and reporting. Choose a pattern from ALL · ARBITRARY · BY_RESOURCE_TYPE and an aggregation from SUM · MEAN · MAX.

At scale

Firewall Manager policies

An AWS Firewall Manager Shield Advanced policy automatically applies protection to in-scope resources across all accounts in your organization, including newly created ones.

Cost protection: charges from protected resources scaling due to a DDoS attack can be reimbursed as service credits by request to AWS Support. This applies when you fulfill the 1-year subscription commitment.

Protected resources

Resources protected by Shield Advanced

Shield Advanced protects only the resources you designate. Some types are protected directly, others through an associated Elastic IP. Only IPv4 is supported.

EdgeGlobal

CloudFront · Route 53 · Global Accelerator

Resources that receive traffic at edge locations. CloudFront also gets L7 protection through a web ACL; for Global Accelerator, only standard accelerators are protected.

Elastic Load Balancing

ALBs and Classic Load Balancers are protected directly; an NLB is protected by protecting its associated Elastic IPs. ALBs also get L7 protection through a web ACL.

Protecting an Elastic IP also protects the EC2 instance or NLB associated with that address. Use it for servers that face the internet directly.

Other types, such as Gateway Load Balancer and Global Accelerator custom routing accelerators, cannot be protected. NAT gateways are outbound-only and are not eligible.

Reference architecture

Consolidate entry points at the edge and protect them there

Web traffic flows through CloudFront and AWS WAF to the ALB origin; TCP · UDP traffic flows through Global Accelerator to the NLB. Apply Shield Advanced protection to the entry-point resources, and use health checks and protection groups to improve detection accuracy.

Getting started

Turning on Shield Advanced

  1. STEP 1

    Subscribe

    Subscribe to Shield Advanced in the account that owns the resources to protect. It is a 1-year commitment that renews automatically.

  2. STEP 2

    Add protections

    Select entry-point resources and add protection. For multiple accounts, use a Firewall Manager policy.

  3. STEP 3

    L7 · health checks

    Add the Anti-DDoS managed rule group to the CloudFront · ALB web ACL and associate Route 53 health checks.

  4. STEP 4

    Prepare for SRT

    Create the SRT access role and register proactive engagement contacts.

  5. STEP 5

    Groups and alarms

    Create protection groups and set SNS alarms on the CloudWatch DDoSDetected metric (DDoSAttackRequests for L7).

Pricing

Cost components

Shield Standard has no additional charge. Shield Advanced consists of a monthly subscription fee and a data transfer usage fee on data out of protected resources.

AWS WAF · Web application firewall · L7

Inspects HTTP requests and decides in rule order

AWS WAF is a managed web application firewall that inspects HTTP(S) requests sent to resources such as CloudFront, ALB, and API Gateway. You stack rules in a web ACL by priority, and each request is handled with one of Allow, Block, Count, CAPTCHA, or Challenge.

Why AWS WAF

When decisions must be based on request content, not ports

Security groups and Network Firewall look at addresses, ports, and flows. SQL injection, credential stuffing, and scraping bots happen inside legitimate HTTPS sessions, so you need an L7 layer that examines headers, query strings, bodies, and client behavior.

Inline

A firewall attached to the service

No separate appliance or routing changes: associate a web ACL with a resource such as a CloudFront distribution or ALB, and inspection starts immediately.

Managed

Move fast with managed rules

Use AWS Managed Rules and AWS Marketplace rule groups to block common web exploits, low-reputation IPs, and bots first, then layer custom rules on top.

Observe

Observe with Count first

Add rules in Count mode, check for false positives with CloudWatch metrics, sampled requests, and full logs, then switch them to Block.

Rules · labels

Rules are JSON statements; labels carry decisions forward

Below is a rate-based rule that limits requests per IP on the login path, excluding requests that carry the corporate-IP label. Using labels added by earlier rules as conditions in later rules lets you split rules into small pieces and combine them.

  1. Evaluated in priority order Priority

    A web ACL evaluates rules from the lowest number up. It stops at a terminating action such as Allow or Block; if nothing matches, the web ACL default action applies.

  2. Count and labels Label

    Count is a non-terminating action that records the match and moves on to the next rule. Labels added by rules and managed rule groups can be referenced by later rules in the same web ACL with LabelMatchStatement.

  3. Rate-based rule 60–600s

    Choose an evaluation window of 60, 120, 300, or 600 seconds; the minimum limit is 10. Requests are aggregated by combining keys such as IP, forwarded IP, headers, query arguments, and label namespaces. It is meant to curb high request rates, not to enforce precise quotas.

Features

Key features

Managed rules

AWS Managed Rules

Use versioned rule groups such as Core rule set, Known bad inputs, SQL database, and IP reputation. Override the action of individual rules in a group, or narrow their scope with a scope-down statement.

Bot Control

Bot detection and management

The Common level classifies self-identifying bots and labels them; the Targeted level also catches bots that hide their identity, using browser interrogation and behavioral analysis. Useful bots such as search engines are allowed after verification.

Fraud Control

ATP · ACFP

ATP detects credential stuffing and account takeover attempts on login pages; ACFP detects fake account creation on sign-up pages. Decisions use compromised-credential checks and session-level aggregation.

CAPTCHA · Challenge

Human and browser verification

CAPTCHA asks the user to solve a puzzle; Challenge silently checks the browser environment. On success, an AWS WAF token is issued and the client isn't asked again during the immunity time.

App integration

Client integration SDKs

With the JavaScript, iOS, and Android SDKs, clients acquire a token in advance and attach it to requests. SDK integration is recommended to get the full benefit of Bot Control Targeted and Fraud Control.

Logging

Full request logs

Send web ACL logs to CloudWatch Logs, Amazon S3, or Amazon Data Firehose. Destination names must start with aws-waf-logs-; use field redaction and log filtering to reduce volume.

L7 DDoS

Anti-DDoS managed rule group

AWSManagedRulesAntiDDoSRuleSet learns a per-resource traffic baseline and detects L7 DDoS within seconds. Low-suspicion requests are mitigated with a silent Challenge and high-suspicion requests with Block. It is a paid rule group.

AI traffic

AI bot and agent management

Bot Control classifies AI crawlers and agents and shows them in the AI activity dashboard. Bots verified with Web Bot Auth signatures are allowed by default, and on CloudFront you can also charge with HTTP 402 through AI traffic monetization.

Request handling

Label forwarding and normalization

Dynamic label interpolation inserts label namespaces, client IP, and JA3 · JA4 fingerprints into custom headers or response bodies with a single rule. Pre-parse text transformation normalizes query strings before parsing to prevent evasion.

Custom responses: specify a status code, headers, and body on a Block action to return a custom response, and with Allow or Count you can insert custom headers into requests forwarded to the origin.

Protected resources

Resources you can associate a web ACL with

One web ACL can be associated with multiple resources of the same scope, but each resource can have only one web ACL. Create web ACLs for CloudFront in the global scope, and all others in the same Region as the resource.

EdgeGlobal scope

Amazon CloudFront · AWS Amplify

Requests are inspected at edge locations, so attack traffic never reaches the origin. The CloudFront body inspection limit is 16 KB by default and can be raised to 64 KB.

Reference architecture

Filter at the edge first, and apply one baseline across the organization

Web traffic is inspected first at CloudFront, which has a global web ACL associated. The Regional API Gateway gets a Regional web ACL. Firewall Manager enforces common rule groups across every account in the organization, and logs from each web ACL are collected in one place.

Getting started

Steps to deploy your first web ACL

  1. STEP 1

    Create a web ACL

    Choose the scope of the resources to protect (CloudFront or Regional) and set the default action. The new console shows it as a protection pack.

  2. STEP 2

    Add managed rules

    Add AWS Managed Rules such as Core rule set and IP reputation, and check WCU usage.

  3. STEP 3

    Observe with Count

    Keep rules in Count, enable logging and CloudWatch metrics, find false positives, and create exceptions.

  4. STEP 4

    Switch to Block

    Switch verified rules to Block first, then add rate-based rules and Bot Control.

  5. STEP 5

    Scale to the organization

    Use Firewall Manager policies to apply common rule groups automatically to all accounts and new resources.

Pricing

Cost components

You pay for what you use. The basics are monthly charges per web ACL and per rule, plus the number of requests processed; enabling intelligent threat mitigation features and extended options adds charges.

For CloudFront distributions you can also choose flat-rate pricing plans (launched November 2025) that include AWS WAF and DDoS protection in a monthly fee.

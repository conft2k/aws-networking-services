Amazon CloudFront · Content delivery network

Respond from the edge closest to users, and keep your origin hidden

CloudFront receives user requests at the edge location with the lowest latency and serves them from cache. Only requests that miss the cache travel over the AWS network to the origin, which can sit in a private subnet or a private S3 bucket.

Why CloudFront

The closer the response, the faster it is and the less your origin works

To deliver content and APIs with the same quality to users at home and abroad, finish requests close to users and reduce the number of requests that reach the origin.

Cache

Tiered caching

POPs, regional edge caches, and Origin Shield absorb requests in turn, reducing load on the origin.

Protect

Attacks stopped at the edge

Shield Standard blocks network- and transport-layer DDoS, and AWS WAF filters application-layer requests.

Program

Code that runs at the edge

CloudFront Functions and Lambda@Edge handle headers, URLs, and authentication logic in front of the origin.

Request path

How a request reaches the origin

DNS routes users to the POP with the lowest latency, and a cache miss moves on to the next tier. Proxy methods such as PUT, POST, PATCH, OPTIONS, and DELETE, and dynamic requests, bypass the regional edge cache and go directly from the POP to the origin.

Features

Key features

S3 origin

Origin Access Control

Lets only CloudFront read your S3 bucket without making it public. It supports SSE-KMS encrypted objects and PUT and DELETE requests, and is the recommended replacement for legacy OAI.

Private origin

VPC origins

Use ALBs, NLBs, and EC2 instances in private subnets as origins. CloudFront reaches them through service-managed ENIs, so origins need no public IP. The VPC must have an internet gateway attached, and you can use VPC origins shared from other accounts through AWS RAM.

Availability

Origin failover

Group a primary and a secondary origin into an origin group. On specified status codes, connection failures, or timeouts, CloudFront retries GET, HEAD, and OPTIONS requests on the secondary.

Edge security

AWS WAF · Shield

Associate a web ACL with a distribution to inspect L7 requests. Shield Standard applies to every distribution at no extra charge, and you can upgrade to Shield Advanced.

Client identity

Viewer mTLS

Validates client X.509 certificates against a trust store at the edge, blocking untrusted clients before they reach your application. You can add validation logic with a Connection Function, check OCSP revocation, and use passthrough mode to forward certificates to the origin. There is no additional charge.

Pricing

Flat-rate pricing plans

Bundles CDN, AWS WAF and DDoS protection, bot management, Route 53 DNS, CloudWatch Logs ingestion, edge compute, and S3 storage credits into a flat monthly price per distribution. There are four tiers (Free, Pro, Business, and Premium) with no overage charges.

Edge compute

CloudFront Functions and Lambda@Edge

Put lightweight, short-running logic such as header manipulation, URL rewrites, and token validation in CloudFront Functions, and logic that needs network calls or access to the request body in Lambda@Edge.

Reference architecture

CloudFront as the single public entry point

Dynamic requests go through a VPC origin to an ALB in a private subnet, and static files go to S3 protected by OAC. An origin group with the ALB as primary and an S3 static page as secondary keeps responses flowing during failures.

Getting started

Steps to launch a distribution

  1. STEP 1

    Prepare the origin

    Set up an S3 bucket or an ALB in a private subnet. Neither needs to be public.

  2. STEP 2

    Create a distribution

    Register the origins, then attach OAC to S3 and a VPC origin to the ALB.

  3. STEP 3

    Configure cache behaviors

    For each path pattern, set the cache policy, origin request policy, and allowed methods.

  4. STEP 4

    Domain · Certificate

    Add alternate domain names and attach an ACM certificate from us-east-1.

  5. STEP 5

    Connect DNS

    Create a Route 53 alias record that points to the distribution, and verify caching behavior with response headers.

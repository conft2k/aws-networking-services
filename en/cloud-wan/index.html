AWS Cloud WAN · Global core network

Run your multi-Region network from a single policy document

With AWS Cloud WAN, you declare Regions, segments, and attachment rules in a JSON policy, and AWS creates a core network edge in each Region and meshes them together. A single policy replaces building a Transit Gateway per Region and managing peering routes by hand.

Why Cloud WAN

Routing intent should live in one place, however many Regions you add

When you build a global network from per-Region Transit Gateways, peering, and static routes, configuration scatters with every Region you add. With Cloud WAN, you declare the desired state, review the changes, and then apply them.

Declare

Declarative policy

Segments, Regions, and attachment mapping rules are managed as policy versions. Review changes before applying them, and roll back to a previous version when needed.

Segment

Global segments

A segment is a routing domain that spans all Regions. By default, communication happens only within the same segment, much like a VRF in MPLS.

Mesh

Automatic inter-Region connectivity

Adding a Region to the policy creates a core network edge that joins the other edges in a full mesh. Inter-Region routes propagate dynamically.

Policy anatomy

Building blocks of a core network policy

A policy document has eight top-level keys. The first three are required; add the rest as needed.

versionrequired

The policy syntax version. Specify 2025.11 to use Routing policy and BGP community propagation.

core-network-configurationrequired

Global settings such as ASN ranges, the Regions that host edges (edge-locations), and VPN ECMP, DNS, and security group referencing support.

segmentsrequired

Defines routing domains. For each segment, set the Regions it uses, whether attachments require acceptance, and whether attachments are isolated from each other.

network-function-groupsoptional

Groups of attachments that host firewalls or IDS/IPS. They are the targets of service insertion.

segment-actionsoptional

Defines route sharing between segments, static routes, service insertion, and Routing policy associations.

attachment-policiesoptional

Automatically maps attachments to segments or network function groups based on conditions such as tags.

routing-policiesoptional

Rules for route filtering, summarization, and BGP attribute changes in the inbound or outbound direction.

attachment-routing-policy-rulesoptional

Specifies which Routing policy applies to attachments that match a Routing policy label condition.

Features

Key features

Auto mapping

Attachment policies

Assigns a segment automatically based on an attachment's tags. For segments that require acceptance, the network team reviews the attachment before it connects.

Service insertion

Network function group

Use send-via to steer traffic between segments, and send-to to steer traffic bound for the internet or on-premises, through an inspection VPC. send-via supports single-hop or dual-hop.

Hybrid

Direct Connect gateway attachment

Attach a DX gateway directly to the core network. On-premises routes learned over a transit VIF propagate to every Region in the segment, with no intermediate Transit Gateway.

Route control

Routing policy

Match routes by prefix, prefix list, AS-PATH, BGP community, or MED to filter or summarize them, and tune path preference with Local Preference, AS-PATH, and MED. Applies to attachments as well as segment sharing and inter-Region routes.

SD-WAN

Tunnel-less Connect

SD-WAN appliances in a VPC peer with the core network edge over BGP without GRE tunnels. Up to 100 Gbps per Connect peer, per AZ.

Migration

Transit Gateway peering

Peer an existing Transit Gateway with the core network edge in the same Region and attach Transit Gateway route tables to segments to migrate in stages.

Attachment types

Bandwidth and Routing policy support by attachment type

VPCs support inbound route filtering only, while BGP-based attachments also support summarization and BGP attribute changes. Routing policy does not apply to network function groups.

Reference architecture

A core network spanning three Regions

Three core network edges are connected in a full mesh. Each attachment joins a segment based on its tags, and traffic between segments passes through the inspection VPC in a network function group.

Getting started

Steps to stand up a core network

  1. STEP 1

    Create a global network

    In Network Manager, create the global network that will contain the core network.

  2. STEP 2

    Write the policy

    Define ASN ranges, edge Regions, segments, and attachment policies.

  3. STEP 3

    Review and apply changes

    Review the policy version's change set and execute it to deploy the edges.

  4. STEP 4

    Create attachments

    Attach VPCs, VPNs, Connect, and DX gateways with tags, and accept them if required.

  5. STEP 5

    Verify routes

    Check inter-Region and shared routes in each segment's route table.

Pricing

Cost components

Cloud WAN pricing is based on the number of core network edges, the number of attachments and their hours, and the amount of data sent to the core network. Inter-Region transfer, VPN, and Direct Connect connections are charged separately.

Bring only the services you need into your VPC on private IPs

AWS PrivateLink brings services into your VPC on private IP addresses. Reach AWS services, services in other accounts, and partner SaaS without an internet gateway, NAT, or public IPs, and limit what is reachable to individual services.

Why PrivateLink

You don't need to open an entire network to use one service

VPC peering and Transit Gateway open routes between networks. PrivateLink creates only an entry point to a specific service in your VPC; no routes are created to other resources in the other VPC.

Private

No internet exposure

Reach services from private subnets without an internet gateway, NAT, or public IPs.

One-way

One-way connectivity

Only the consumer VPC can initiate connections. No path is created from the provider VPC into the consumer VPC.

Overlap

Overlapping CIDRs allowed

As long as the consumer and provider are in different VPCs, their IP ranges can overlap, because access goes through an ENI inside the consumer VPC.

Provider & consumer

Providers publish services; consumers create endpoints

A PrivateLink connection is completed by work on both sides. The provider puts a service behind a load balancer and publishes it as an endpoint service, and the consumer creates an endpoint in its own VPC to connect to that service.

Consumer

The side that uses the service

  • subnetPick a subnet per AZ to create an interface endpoint. One ENI is created in each AZ.
  • SGAttach security groups to the endpoint ENIs to restrict which clients can connect.
  • DNSWith private DNS enabled, clients reach the endpoint using the existing service name.
consumer → provider
one-way
Provider

The side that publishes the service

  • NLBPut the service behind a Network Load Balancer and create an endpoint service. Appliances use a Gateway Load Balancer.
  • allowSpecify the AWS accounts or IAM principals allowed to connect, and optionally require manual acceptance of requests.
  • regionAdd supported Regions so consumers in other Regions can create endpoints too.

Features

Key features

Cross-Region

Cross-Region PrivateLink

Connect with an interface endpoint to endpoint services and select AWS services (S3, IAM, ECR, and others) in another Region. You don't need to match AZs with the provider, and connections to AWS services can use only the Regional DNS name. PrivateLink manages failover across AZs but not across Regions.

Name resolution

Private DNS

Once the provider verifies and associates a domain name, consumers reach the endpoint with the same name without changing application settings.

Access control

Endpoint policy

Attach a resource policy to the endpoint to restrict the principals, actions, and resources that can be called through it.

Hybrid

Access from on-premises

Traffic arriving over Direct Connect, Site-to-Site VPN, Transit Gateway, Cloud WAN, or VPC peering also reaches the endpoint.

VPC Lattice

Resource endpoint

Reach databases, domain names, or IP targets in other VPCs or on-premises over TCP without a load balancer. The provider shares resources through a resource gateway.

Inspection

Gateway Load Balancer endpoint

Set it as the next hop in a VPC route table to send traffic to a fleet of virtual appliances such as firewalls.

Reference architecture

Connect just the service, even with overlapping IP ranges

Even when the consumer and provider VPCs both use 10.0.0.0/16, the interface endpoint connects to the service. On-premises reaches the endpoint through the consumer VPC, and consumers in other Regions use cross-Region PrivateLink.

Getting started

Steps to publish your service with PrivateLink

  1. STEP 1

    Prepare an NLB

    Create a Network Load Balancer and target group across two or more AZs in the provider VPC.

  2. STEP 2

    Create the endpoint service

    Select the NLB to create an endpoint service, and add the principals allowed to connect.

  3. STEP 3

    Create the endpoint

    The consumer creates an interface endpoint using the service name and picks subnets and security groups.

  4. STEP 4

    Accept the connection

    If acceptance is required, the provider accepts the connection request.

  5. STEP 5

    Test with DNS

    Connect to the service using the endpoint DNS name or the private DNS name.

Pricing

Cost components

PrivateLink pricing is based on the hours an endpoint is provisioned and the amount of data it processes. The provider-side load balancer and inter-Region transfer are charged separately.

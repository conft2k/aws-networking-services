Amazon API Gateway · Managed API front door

Authorize and control every API call at a single point

API Gateway is the front door for REST, HTTP, and WebSocket APIs. It authorizes requests, throttles traffic that exceeds limits, and forwards calls to Lambda or to services inside a VPC. You can also build private APIs that are callable only from within a VPC.

Why API Gateway

More APIs call for a common gateway

When every service implements its own authorization, throttling, and logging, policies drift apart and operational overhead grows. Apply common policies at the gateway and let backends focus on business logic.

Secure

Authorize at the gateway

Verify callers with IAM, a Lambda authorizer, Cognito, or JWT before requests reach the backend.

Control

Traffic limits

Apply token bucket limits per account, per stage and method, and per client.

Private

Private paths

Expose APIs only to VPCs and on-premises networks through interface VPC endpoints, and reach private backends through VPC links.

API types

REST, HTTP, WebSocket API

HTTP APIs offer a reduced feature set at a lower price, while REST APIs include management features such as private endpoints, API keys, caching, and AWS WAF. Use WebSocket APIs for two-way real-time communication.

Choose based on whether the caller is a workload with AWS credentials or an app holding a user token.

IAM permissions

IAM policies evaluate requests that callers sign with SigV4. REST APIs can also restrict source VPCs, VPC endpoints, and accounts with a resource policy.

Features

Key features

Private endpoint

Private API

A REST API that can be called only through an execute-api interface VPC endpoint. Traffic never traverses the internet, and on-premises clients can call it over Direct Connect.

Private domain

Private custom domain

Give a private API an internal domain name managed with an ACM certificate. Share it with other accounts through AWS RAM; consumer accounts associate it with their VPC endpoints.

Throttling

Tiered limits

Rate and burst limits apply at the AWS Region, account, stage and method, and client levels. Requests over the limit receive a 429 response.

API management

Usage plan · API key

On REST APIs, identify clients with API keys and set per-client request limits and usage quotas per period.

Custom domain

Custom domains · mTLS

Map multiple APIs and stages to a domain such as api.example.com. Both REST and HTTP APIs can verify client certificates with mutual TLS. REST APIs can split requests across APIs and stages with header-based routing rules, and can also apply mTLS to backend integrations with an ACM certificate.

Private integration

VPC link

Both REST and HTTP APIs connect directly to an ALB in private subnets through VPC link v2, and NLBs are also supported. HTTP APIs can also route to services registered in AWS Cloud Map.

Streaming

REST API response streaming

Stream responses from Lambda, HTTP proxy, and private integrations to clients as they are generated. Time to first byte improves, integration timeouts extend up to 15 minutes, and responses can exceed 10 MB.

Developer portal

API Gateway Portals

A managed developer portal that discovers the APIs in your account, generates documentation, and publishes them to internal and external developers grouped as PortalProducts. It provides access control and usage analytics based on CloudWatch RUM.

AI agents

MCP proxy

Connect existing REST APIs to Amazon Bedrock AgentCore Gateway and expose them as MCP-compatible endpoints. AI agents discover and call the APIs as tools without any application changes.

Integration types

How requests reach the backend

Integration types for REST APIs. Proxy types pass requests and responses through unchanged; non-proxy types transform them with mappings.

AWS_PROXY

Lambda proxy

Passes the entire request to a Lambda function. This is the recommended way to invoke Lambda.

HTTP_PROXY

HTTP proxy

Passes requests and responses to and from an HTTP endpoint unchanged. Use it with a VPC link for private backends.

AWS · HTTP

Mapped integration

Calls an AWS service action or an HTTP endpoint, with integration request and response mappings that you define.

MOCK

Mock

API Gateway responds without calling a backend. Use it for testing and parallel development.

Reference architecture

A private API open only to VPCs and on-premises

The private REST API is called only through an execute-api interface endpoint, and a resource policy specifies which VPC endpoints are allowed. On-premises clients come in over Direct Connect and resolve names through a Resolver inbound endpoint.

Getting started

Steps to launch a private API

  1. STEP 1

    Create the endpoint

    Create an execute-api interface endpoint in the consumer VPC and allow port 443 in its security group.

  2. STEP 2

    Create the private API

    Create a REST API with the Private endpoint type.

  3. STEP 3

    Resource policy

    Specify the allowed VPC endpoints with the aws:SourceVpce condition.

  4. STEP 4

    Integrate · deploy

    Attach a Lambda or VPC link integration to each method and deploy to a stage.

  5. STEP 5

    Test calls

    Call the API from inside the VPC; on-premises clients resolve its name through the Resolver inbound endpoint.

Pricing

Cost components

API Gateway has no minimum fees or commitments. Cost is based on API calls received, WebSocket messages and connection minutes, and data transferred out. How the Free Tier applies depends on when the account was created.

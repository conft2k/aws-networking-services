Why Route 53

DNS is the first hop of every connection

If name resolution fails, the service stops even when the network is healthy. Design the availability of authoritative DNS, the health information reflected in answers, and the resolution paths between VPCs and on-premises together.

Available

Authoritative DNS built for availability

The SLA commits to 100% monthly availability per hosted zone. With accelerated recovery turned on, you can change public records again within an hour even during a us-east-1 outage.

Aware

Answers that know health

Combine health checks with routing policies so only healthy endpoints appear in answers.

Hybrid

One resolution path

Resolver endpoints and rules let VPC and on-premises DNS resolve each other's domains.

Features

Main features

Health checks

Health checks

Check endpoints over HTTP, HTTPS, or TCP, or create calculated checks that combine other health checks and checks based on CloudWatch alarms. You can also match a string in the HTTP response body.

Hybrid DNS

Resolver endpoints

Created as ENIs in VPC subnets and require at least two IP addresses. Placing them in two or more Availability Zones is recommended. Inbound supports Do53, DoH, and DoH-FIPS; outbound supports Do53 and DoH. You can also create delegation endpoints that receive subdomains delegated by NS records.

Forwarding

Resolver rules

Decide, per domain, which DNS servers receive queries. Besides forwarding rules, delegation rules hand subdomains to your corporate DNS. Associate rules with VPCs and share them with other accounts through AWS RAM.

DNS security

DNS Firewall

Applies ALLOW, ALERT, or BLOCK to outbound queries through the VPC Resolver based on domain lists. DNS Firewall Advanced detects DNS tunneling and DGA domains, and you can add Palo Alto Networks Advanced DNS Security rules.

Multi-account

Route 53 Profiles

Bundle private hosted zones, Resolver rules, DNS Firewall rule groups, interface VPC endpoints, and query logging configurations into one Profile and apply it to many VPCs and accounts.

Anycast resolver

Route 53 Global Resolver

An internet-reachable anycast resolver that lets authenticated clients resolve public domains and private hosted zones from anywhere. Generally available since March 2026, it accepts IPv4 and IPv6 queries and provides query filtering and centralized logging.

Reference architecture

Hybrid DNS through a shared services VPC

Place Resolver endpoints in a shared services VPC, and deploy rules and private hosted zones to workload VPCs with a Profile. Query direction is the key. Inbound receives aws.corp.internal queries in the on-premises → AWS direction; outbound forwards corp.internal queries to corporate DNS in the AWS → on-premises direction. Queries arriving through the inbound endpoint are resolved in the context of the VPC that holds the endpoint, so the private hosted zone must also be associated with the shared services VPC.

Reference architecture · Global Resolver

Global Resolver: query the same anycast addresses from anywhere

Branches, data centers, and remote users query the same two anycast IPs over the internet, without VPNs or Resolver endpoints. Queries are handled in the nearest of two or more Regions you choose, and if that Region stops, the next-nearest Region takes them on the same addresses. Each Region authenticates the client, applies the filtering rules in the DNS view, and resolves through the private hosted zones associated with the view or through public DNS.

Getting started

Steps to set up hybrid DNS

  1. STEP 1

    Prepare security groups

    Allow TCP and UDP 53 in the endpoint security group. If you use DoH, also open 443.

  2. STEP 2

    Create endpoints

    Create inbound and outbound endpoints in the shared services VPC across two or more AZs.

  3. STEP 3

    Write forwarding rules

    On the outbound endpoint, create rules that send corporate domains such as corp.internal to your corporate DNS server IPs.

  4. STEP 4

    Deploy to VPCs

    Put the rules and private hosted zones in a Profile, associate it with workload VPCs, and share it with accounts through RAM.

  5. STEP 5

    Configure corporate DNS

    Add conditional forwarding on your corporate DNS that sends AWS domains to the inbound endpoint IPs, then verify both directions with dig.

Pricing

Cost components

Route 53 costs are driven by the number of hosted zones, query volume and routing policy type, the number of health checks, and Resolver endpoint ENI hours. In hybrid DNS, the number of endpoint ENIs becomes a fixed cost.

AWS Firewall Manager · Organization-wide security policies · Compliance

Define security rules once and enforce them across your organization

AWS Firewall Manager is a management service that centrally deploys AWS WAF, Shield Advanced, security group, network ACL, Network Firewall, and DNS Firewall policies across the accounts and resources in AWS Organizations. New accounts and resources are protected automatically as soon as they fall within a policy's scope.

Why Firewall Manager

The more accounts you add, the more your firewall settings drift apart

Managing web ACLs, security groups, and firewall rules separately in each account leads to gaps and exceptions. With Firewall Manager, the security team defines the baseline as policies, and application teams add their own rules on top.

Central

Define once, deploy everywhere

A policy created in the administrator account deploys the same protection to every account and resource in scope. When you change the policy, the change propagates too.

Automatic

New accounts and resources, too

When an account joins the organization or a matching resource is created, Firewall Manager evaluates it and applies the policy right away.

Audit

Find and surface violations

A per-policy compliance dashboard shows noncompliant accounts and resources and the reasons. You can also start in report-only mode without auto remediation.

Prerequisites

What you need before creating policies

Firewall Manager is an organization-level service. Complete the steps below in order before you can create policies in the console.

  1. 01

    Enable all features in AWS Organizations

    Managed accounts must belong to one organization, and all features must be enabled, not just consolidated billing.

  2. 02

    Designate a default administrator

    The management account onboards the organization to Firewall Manager and designates the default administrator. The default administrator has full scope and also manages third-party firewall policies. A dedicated security account is typical.

  3. 03

    Enable AWS Config

    Turn on AWS Config in every member account and Region that has resources to protect. Firewall Manager uses Config to detect resource changes and evaluate compliance.

  4. 04

    Policy type–specific setup

    Network Firewall and DNS Firewall policies require AWS RAM resource sharing with your organization, and third-party firewall policies require an AWS Marketplace subscription and integration setup. Regions that are disabled by default must be enabled separately.

Policy types

What you can manage with policies

Each Firewall Manager policy covers a single type. To enforce multiple protections, create a policy per type; you can also have several policies of the same type. Policies are Regional, and policies that target CloudFront are created as global.

L7 · Web

AWS WAF policy

Associates a Firewall Manager–managed web ACL with resources in scope. The policy's first rule groups are pinned at the start and its last rule groups at the end, and account owners add their own rules in between. With the retrofit option, policy rules are added to web ACLs that are already associated.

Features

Key features

Policy scope

Scope by account, resource, and tag

Apply to the whole organization, only to specified accounts and OUs, or to everything except specified accounts and OUs. Choose resource types, then include or exclude resources by whether they have all of the tags (AND) or any of them (OR). You can also group resources directly with a resource set.

Remediation

Auto remediation or report only

Choose whether to fix noncompliant resources automatically or just report them without changes. Options also let you remove protection from resources that leave scope and clean up resources Firewall Manager created.

Compliance

Per-policy compliance dashboard

Each policy shows how many accounts are in scope and how many are compliant, and you can drill down from noncompliant account → resource → violation reason. Get real-time notifications of new violations through an Amazon SNS channel.

Security Hub

Security Hub CSPM findings

Sends noncompliant resources and detected attacks to Security Hub CSPM as findings. The integration is enabled automatically when you use Firewall Manager, so you can prioritize them alongside results from other security services.

Managed lists

Application and protocol lists

Define the ports and protocols to allow or deny in security group policies as managed lists and reuse them. Use AWS-provided lists together with your own.

Logging

Centralized WAF logging

When you enable logging in an AWS WAF policy, web ACL logs from every account in scope are collected into Amazon Data Firehose or S3 in a single account. Sensitive fields are redacted by the policy.

Recent updates: AWS WAF L7 Anti-DDoS managed rule group can be added to policies (June 2025), Firewall Manager API calls through AWS PrivateLink interface endpoints (July 2025), and launches in the Asia Pacific (Taipei) Region (September 2025) and Asia Pacific (New Zealand) Region (March 2026). With retrofit existing web ACLs in AWS WAF policies, you can keep the web ACLs application teams created and just add the policy rules.

Network Firewall via FMS

Three management types for Network Firewall policies

A Network Firewall policy's firewall management type determines where firewalls are created. Create the rule groups in the administrator account in advance and deploy them to member accounts through AWS RAM organization sharing.

  1. D

    Distributed

    Creates a firewall in each VPC of in-scope accounts, with endpoints in a firewall subnet per AZ. Routing is set to Monitor mode, which only reports violations, or Off.

  2. C

    Centralized

    Creates a single firewall in one inspection VPC in a specified account. Suits designs that aggregate spoke VPC traffic through Transit Gateway for inspection; you configure routing yourself.

  3. I

    Import existing firewalls

    Brings firewalls you already run under a single policy and adds organization baseline rules to standardize them.

Rule evaluation order: the policy selects strict order or action order for stateful rules. The Firewall Manager API documents that StatefulEngineOptions.RuleOrder defaults to DEFAULT_ACTION_ORDER when omitted, so set it explicitly if you want strict order, the Network Firewall console default.

Reference architecture

Push policies from the security account and collect the results back

The management account designates the security account as the Firewall Manager administrator. The administrator creates policies and deploys them per OU; when AWS Config in each member account detects a change, Firewall Manager re-evaluates compliance. Violations are collected in the dashboard and Security Hub CSPM.

Getting started

Steps to apply your first policy

  1. STEP 1

    Organization and admin

    Enable all features in Organizations, and designate the security account as the default administrator from the management account.

  2. STEP 2

    Turn on AWS Config

    Enable Config in every account and Region with resources to protect. Enable RAM sharing with your organization if needed.

  3. STEP 3

    Create a policy

    Choose the policy type and Region (Global for CloudFront), then fill in the contents such as rule groups or the baseline security group.

  4. STEP 4

    Scope and report only

    Set the scope by account · OU, resource type, and tags, and review violations with auto remediation turned off.

  5. STEP 5

    Switch to auto remediation

    After confirming the impact, turn on auto remediation and keep tracking violations with Security Hub CSPM and SNS.

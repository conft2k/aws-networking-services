Why Site-to-Site VPN

Start your hybrid network on the internet connection you already have

Use it right away, even while a dedicated circuit is being provisioned, and at low-traffic sites such as branches. Alongside Direct Connect, it serves as a backup path or as an encryption layer over the dedicated circuit.

Ready

Use existing equipment

Any router, firewall or software appliance that supports IPsec can be the customer gateway. Download device-specific configuration files from the console.

HA

Redundant tunnels

Every connection includes two tunnels for high availability. Configure both, and the connection stays up when one tunnel goes down for maintenance or a failure.

Flexible

Three termination points

Connect to a virtual private gateway for one VPC, a transit gateway for many VPCs, or Cloud WAN for a global network.

Tunnel build-up

How a tunnel comes up

Each tunnel builds a security association with IKE, wraps traffic in IPsec, and exchanges routes over its inside addresses. Troubleshoot in the same order.

BGPRouting

Inside addresses and route exchange

Each tunnel uses a /30 inside address from 169.254.0.0/16. Dynamic connections run BGP sessions over these addresses; static connections forward only the prefixes you specify.

Routing

Static or BGP

You choose the routing type when you create the connection. If the same route exists on a virtual private gateway as both static and BGP, the static route is preferred.

Dynamic

BGP routing

Recommended if your device supports BGP. Routes are exchanged automatically, and traffic fails over to the other tunnel if one fails.

  • On Transit Gateway, ECMP can aggregate bandwidth across tunnels.
  • Routes received from the customer gateway: 100 for VGW, 1,000 for Transit Gateway
Static

Static routing

For devices that don't support BGP. You register on-premises prefixes on the connection directly.

  • ECMP is not supported.
  • Not available for Cloud WAN connections or VPN Concentrator.
  • Static routes per VGW connection: 100

Features

Key features

Acceleration

Accelerated VPN

AWS Global Accelerator receives traffic at the edge location nearest the customer gateway and carries it over the AWS global network. Available on Transit Gateway connections (not VGW), and can be enabled only at connection creation.

Over Direct Connect

Private IP VPN

Build IPsec tunnels with private IPs over a transit VIF and DX gateway. Encrypts dedicated-circuit traffic without public IPs.

Bandwidth

Large Bandwidth Tunnel

Up to 5 Gbps per tunnel on Transit Gateway or Cloud WAN connections. Both tunnels use the same bandwidth, and it can't be combined with Accelerated VPN. Existing connections can switch between standard and Large while keeping tunnel IPs and settings.

Observability

Tunnel logs

Send IKE, IPsec and DPD activity logs and BGP status and route change logs to Amazon CloudWatch Logs. Find the cause of negotiation failures without device logs.

Dual stack

IPv6 tunnels

On Transit Gateway and Cloud WAN, combine IPv4 and IPv6 for outer tunnels and inner traffic. Virtual private gateways support IPv4 only.

Many sites

VPN Concentrator

Connect up to 100 small sites of up to 100 Mbps each to Transit Gateway through a single concentrator. The concentrator appears as one Transit Gateway attachment, and sites share a total of 5 Gbps. BGP routing only.

Reference architecture

Internet VPN and VPN over Direct Connect

The branch builds two tunnels over the internet to the transit gateway and exchanges routes over BGP. The data center reaches the same transit gateway through a transit VIF and DX gateway, and adds encryption on top with a Private IP VPN.

Getting started

How to set up a VPN connection

  1. STEP 1

    Customer gateway

    Create a customer gateway with your on-premises device's public IP (or certificate) and BGP ASN.

  2. STEP 2

    Prepare the termination

    Attach a virtual private gateway to the VPC, or prepare a transit gateway or Cloud WAN.

  3. STEP 3

    Create the VPN connection

    Choose the routing type and tunnel options and, if needed, acceleration and tunnel bandwidth.

  4. STEP 4

    Configure the device

    Download the configuration file for your device vendor and configure both tunnels.

  5. STEP 5

    Verify routing

    Enable route table propagation, then check tunnel status, BGP sessions and received routes.

Amazon VPC Lattice · Application networking

Connect and control traffic per service, across VPCs and accounts

Amazon VPC Lattice brings services and resources spread across multiple VPCs and accounts into a single service network. You define routing, authentication, and logging per service, without building network connectivity between VPCs yourself.

Why VPC Lattice

Connect services, not VPCs

When you open service-to-service traffic with VPC peering or Transit Gateway, CIDR planning, route tables, and security group rules grow with every VPC. VPC Lattice makes the service the unit of communication, so network and application teams each manage only their own part.

Connect

Works with overlapping CIDRs

VPC Lattice supports overlapping CIDRs. Call services across VPCs and accounts without redesigning your address plan.

Secure

Per-request authentication

Use IAM auth policies alongside security groups to decide who can call which service. Authenticated requests are signed with SigV4.

Delegate

Separation of duties

Network administrators manage service networks and policies; service owners manage listeners and target groups. Share across accounts with AWS RAM.

Features

Key features

Routing

Listener rules

Split requests by path, header, or HTTP method. Send traffic to multiple target groups with weights from 0–999 for canary deployments, or return 404 or 500 with a fixed-response action.

Authorization

Auth policy

Attach IAM policies to the service network and to each service. With the AWS_IAM auth type, both policies must explicitly allow a request for it to pass.

Multi-account

AWS RAM sharing

Share services, service networks, and resource configurations with specific accounts, OUs, or your entire organization. Shared services appear in the service directory.

TCP resources

Resource configuration

Expose Amazon RDS databases (ARN), domain names, private IPs, and CIDR ranges over TCP to other VPCs and accounts. A resource gateway is the entry point into the resource VPC. When you add a custom domain, a private hosted zone is created automatically in the consumer VPC, and with DNS resolution set to IN_VPC you can also use private domain names as targets.

Hybrid access

Service network endpoint

Create a VPC endpoint of type service network in a VPC, and on-premises networks connected through Direct Connect or VPN can reach services and resources. A single VPC can also connect to multiple service networks.

Observability

Access logs

Enable access logs per service network, service, or resource configuration, and deliver them to CloudWatch Logs, Amazon S3, or Amazon Data Firehose.

Auth policy

Define who can call what with IAM policies

With the AWS_IAM auth type, the default is deny all. Without a policy, every request receives access denied.

  1. Check the service network policy

    If an auth policy is enabled and there is no explicit allow, the request is denied.

  2. Check the service policy

    If the service also has a policy, the request is evaluated again the same way. Put common rules on the service network and narrower rules on the service.

  3. Check the caller's IAM policies

    The calling role's identity-based policies must also allow the request. An explicit deny in any policy overrides an allow.

Reference architecture

Services and databases from multiple accounts in one network

Client VPCs associate with the service network, and on-premises networks come in through a service network endpoint. Services and databases stay in their owning accounts and are shared with AWS RAM.

Getting started

Steps to connect your first service

  1. STEP 1

    Create a target group

    Choose the target type, protocol, and health checks, then register targets.

  2. STEP 2

    Service and listener

    Create a service and configure the listener protocol, port, and default rule.

  3. STEP 3

    Create a service network

    Choose the auth type (NONE or AWS_IAM) and the access log destination.

  4. STEP 4

    Associate services

    Associate the service with the service network. For services in other accounts, receive them through RAM sharing, then associate.

  5. STEP 5

    VPC association and policy

    Associate the client VPC with security groups, attach an auth policy, and verify calls.

Pricing

Pricing dimensions

Services are billed by running hours, data processed, and number of requests. Resource configurations are billed by hours associated with a service network and data processed.

Why Interconnect

클라우드 간 연결을 직접 짜 맞추지 않아도 됩니다

지금까지 AWS와 다른 클라우드를 사설로 잇으려면 코로케이션, 크로스커넥트, 양쪽 VLAN·BGP를 직접 조율해야 했습니다. Interconnect는 이 과정을 생성 요청과 수락 두 동작으로 줄입니다.

Managed

물리·라우팅 설정은 서비스가

장비 프로비저닝, VLAN, BGP 세션, ASN 할당, 유지보수까지 AWS와 상대 사업자가 맡습니다. 보통 몇 분 안에 연결이 올라옵니다.

Resilient

이중화는 기본값

독립 전원·네트워크를 갖춘 시설 두 곳 이상에서 장비, 크로스커넥트, 시설 단위의 단일 장애점을 없앤 구성으로 프로비저닝됩니다.

Elastic

대역폭은 속성 하나

연결을 다시 만들거나 지원 케이스를 열지 않고 콘솔이나 CLI에서 대역폭을 올리고 내립니다.

How it works

양쪽 attach point 사이에 놓인 객체 하나

AWS와 파트너는 지원 리전과 로케이션에 용량을 미리 깔아 둡니다. 사용자가 요청하면 그 위에 논리 연결을 잘라 양쪽 attach point를 잇고, 결과를 interconnect 객체 하나로 보여 줍니다.

AWSAttach point

Direct Connect Gateway

AWS 쪽 attach point는 항상 DX Gateway입니다. 여기에 Virtual Private Gateway, Transit Gateway, Cloud WAN 코어 네트워크를 연결해 VPC까지 경로를 전달합니다. 기존 Private·Transit VIF가 붙어 있는 DX Gateway도 쓸 수 있습니다.

Features

주요 기능

Multicloud

CSP 간 사설 연결

트래픽은 AWS 글로벌 백본을 타고 가다 상대 CSP에 바로 넘겨집니다. 온프레미스 장비나 가상 라우터를 거칠 필요가 없습니다.

Last mile

기존 회선 사업자로 온보딩

이미 쓰는 사업자(예: Lumen)의 Ethernet·MPLS 회선망에서 바로 AWS로 들어옵니다. IPv4·IPv6를 지원하고, MTU는 8500(점보 프레임)으로 자동 설정됩니다.

Global reach

Cloud WAN 연동

같은 DX Gateway에 붙은 Interconnect는 어느 리전의 Cloud WAN CNE에서도 최단 경로로 닿습니다. VGW·TGW는 Interconnect의 로컬 리전 것만 연결됩니다.

Elastic

무중단 대역폭 변경

대역폭은 연결의 속성일 뿐입니다. 콘솔이나 CLI에서 바꾸면 재생성 없이 반영되므로 피크에 늘리고 평소에 줄일 수 있습니다.

Observability

CloudWatch 모니터링 포함

Interconnect마다 Network Synthetic Monitor 하나가 추가 비용 없이 붙어 왕복 지연과 패킷 손실을 측정합니다. 대역폭 사용률(%) 지표로 경보도 걸 수 있습니다.

Open spec

공개 API 사양

연동 사양을 GitHub에 공개해 Google Cloud, OCI, Azure, Lumen 등이 같은 방식으로 붙습니다. 상대가 늘어도 운영 모델과 도구는 그대로입니다.

Comparison

Direct Connect, VPN과 무엇이 다른가

Interconnect는 Direct Connect 인프라와 DX Gateway 위에서 동작하는 관리형 계층입니다. 포트·VIF·BGP를 직접 다루는 Direct Connect와 달리, 파트너와 미리 맞춰 둔 용량을 객체 단위로 빌려 씁니다.

Reference architecture

DX Gateway 하나에 multicloud와 last mile을 함께

us-east-1을 로컬 리전으로 Google Cloud용 multicloud Interconnect와 Lumen last mile Interconnect를 같은 DX Gateway에 붙인 예입니다. 로컬 리전의 Transit Gateway는 DX Gateway association으로, 다른 리전은 Cloud WAN CNE를 통해 두 Interconnect에 닿습니다.

원격 리전의 TGW를 같은 DX Gateway에 직접 연결할 수는 없습니다. 원격 리전 TGW는 로컬 리전 TGW와 피어링하면 Interconnect에 닿으며, 이때 리전 간 전송 요금과 TGW 데이터 처리 요금이 붙습니다.

Getting started

Interconnect를 만드는 순서

Direct Connect 콘솔의 AWS Interconnect 메뉴, CLI, API, CloudFormation(AWS::Interconnect::Connection)에서 만들 수 있습니다. 어느 쪽에서든 먼저 생성하고, 다른 쪽이 activation key로 수락합니다.

  1. STEP 1

    연결 방식 정하기

    VGW·TGW(로컬 리전)와 Cloud WAN(전역) 중 고르고, IP 대역 충돌을 확인한 뒤 DX Gateway를 준비합니다.

  2. STEP 2

    생성 요청

    상대 CSP나 파트너, AWS 리전(또는 메트로), 대역폭, DX Gateway, 상대 측 ID를 입력합니다.

  3. STEP 3

    activation key 수락

    AWS가 발급한 키로 상대 쪽 콘솔이나 포털에서 수락합니다. 상대가 먼저 만들었다면 AWS 콘솔의 Accept 메뉴에 키를 넣습니다.

  4. STEP 4

    자동 프로비저닝

    연결 4개, VLAN, BGP, ASN, MACsec이 자동 구성됩니다. 이 단계에는 사용자 작업이 없습니다.

  5. STEP 5

    경로와 지표 확인

    DX Gateway 연결을 확인하고, Network Synthetic Monitor와 사용률 지표에 CloudWatch 경보를 겁니다.

프리뷰 상대는 활성화 단계에서 CLI가 필요할 수 있습니다. multicloud Free Tier는 콘솔의 “AWS Interconnect - multicloud - Free Tier” 흐름으로 만들며, 500 Mbps가 미리 선택되어 있습니다. 상대 CSP 쪽 500 Mbps 쿼터도 먼저 확인하세요.

Next step

Free Tier 500 Mbps로 클라우드 간 경로부터 검증해 보세요

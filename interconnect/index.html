이름은 하나, 서비스는 둘입니다

AWS Interconnect는 서로 독립된 두 서비스를 묶은 이름입니다. multicloud는 AWS VPC를 다른 퍼블릭 클라우드의 VPC와, last mile은 지사·데이터센터를 회선 사업자의 기존 망을 거쳐 AWS와 잇습니다. 상대, 지원 리전, 요금표, 쿼터가 서비스마다 따로입니다.

공통점은 운영 모델입니다. 리전, 대역폭, 상대만 고르면 AWS와 상대가 미리 깔아 둔 용량 위에 연결을 만들고, DX Gateway에 붙는 interconnect 객체 하나로 보여 줍니다.

Service 01 · multicloud

Interconnect – multicloud: 다른 클라우드와 바로 잇기

AWS와 상대 CSP가 미리 깔아 둔 용량 풀 위에 전용 대역폭 사설 연결을 만듭니다. 트래픽은 AWS 글로벌 백본을 타고 가다 상대 CSP에 바로 넘겨지므로, 온프레미스 장비나 가상 라우터를 거칠 필요가 없습니다.

Bandwidth

조합별 속도, 무중단 변경

상대·리전 조합이 지원하는 목록에서 고르고, 연결을 다시 만들지 않고 속성만 바꿔 늘리고 줄입니다.

Resiliency

4-way 이중화 + MACsec

시설 2곳 이상의 연결 4개에 ECMP. AWS 라우터와 CSP 라우터 사이 물리 구간은 MACsec으로 암호화됩니다.

Limits

CSP당 2개

계정당 상대 CSP마다 2개까지. 프리뷰 상대는 리전당 1개, 프리뷰 중 활성화에 CLI가 필요할 수 있습니다.

multicloud · architecture

로컬 리전은 TGW·VGW로, 다른 리전은 Cloud WAN으로

us-east-1을 로컬 리전으로 Google Cloud(us-east4)와 잇는 예입니다. VGW·TGW는 같은 리전의 Interconnect에만 닿고, Cloud WAN CNE는 같은 DX Gateway에 붙은 Interconnect라면 어느 리전에서든 닿습니다.

언제 쓰나

클라우드 간 데이터 이동

다른 클라우드의 데이터·분석 서비스와 AWS 워크로드 사이를 인터넷이나 자체 코로케이션 없이 잇습니다.

언제 쓰나

멀티 리전 허브와 연동

Cloud WAN을 쓰면 다른 리전 워크로드도 같은 Interconnect를 씁니다. 단, 가장 먼 CNE 기준으로 요금 Tier가 오릅니다.

언제 쓰나

먼저 무료로 검증

GA 상대에는 Tier 1 500 Mbps Free Tier가 있어 경로와 라우팅을 먼저 확인할 수 있습니다(유료 전환 불가).

Service 02 · last mile

Interconnect – last mile: 지금 쓰는 회선 사업자로 AWS까지

이미 계약한 회선 사업자의 Ethernet·MPLS 망에서 바로 AWS로 들어옵니다. 파트너 탐색, 크로스커넥트, VLAN·ASN·BGP 설정을 서비스가 자동화하고 AWS 권장 구성을 강제합니다. 고객 쪽에는 파트너 망에 붙은 CPE만 있으면 됩니다.

Bandwidth

1–100 Gbps, 7단계

1·2·5·10·25·50·100 Gbps 중에서 고르고, 콘솔이나 CLI에서 재생성 없이 올리고 내립니다.

Resiliency

99.99% SLA (DX 포트까지)

서로 다른 사이트 2곳의 라우터 쌍 4개에 연결 4개를 두고 ECMP로 나눕니다. 계획 유지보수 중에도 링크 하나 이상은 살아 있습니다.

Network

MTU 8500 · IPv4/IPv6

점보 프레임이 기본이고 BGP는 자동 구성됩니다. 모든 연결에 256-bit MACsec이 기본 적용됩니다.

last mile · architecture

메트로에서 AWS로 들어와 DX Gateway로 퍼집니다

사이트의 CPE에서 Lumen 망(퍼스트 마일)을 거쳐 NY/NJ 메트로에서 AWS로 들어오는 예입니다. 워크로드가 us-east-1에 있을 필요는 없고, Cloud WAN을 쓰면 다른 리전에도 닿습니다.

vs 호스팅 연결

조달·설정·이중화 자동

호스팅 연결은 파트너 탐색, 회선 조달, VIF·BGP 설정이 사용자 몫이고 기본 이중화가 아니며 DX SLA 대상이 아닙니다. last mile은 이를 자동화하고 이중화를 강제합니다.

언제 쓰나

지사·데이터센터 온보딩

이미 쓰는 사업자 계정으로 콘솔에서 바로 요청합니다. 기존 Private·Transit VIF가 붙은 DX Gateway에도 연결할 수 있습니다.

운영

지원 창구는 둘

AWS 쪽은 AWS Support, 파트너 망은 파트너가 지원합니다. 파트너당 2개까지 만들 수 있습니다(계정 기준).

Comparison

Getting started

서비스별 생성 순서

둘 다 Direct Connect 콘솔에서 시작하지만 메뉴가 다릅니다. 어느 쪽이 먼저 만들든 상대가 activation key로 수락하면 프로비저닝이 끝까지 자동으로 진행됩니다.

multicloud

DX 콘솔 › AWS Interconnect

  1. 설계 · VGW·TGW(로컬 리전)와 Cloud WAN(전역) 중 고르고 IP 대역 충돌을 확인합니다.
  2. Create new multicloud Interconnect · 상대 CSP 카드(프리뷰는 Preview 표시)를 고릅니다.
  3. 위치·속도 · AWS 로컬 리전, 상대 리전, 대역폭, DX Gateway, 상대 ID를 입력합니다.
  4. 수락 · 발급된 activation key를 CSP 쪽에서 입력합니다. CSP가 먼저 만들었다면 Accept multicloud Interconnect에 키를 넣습니다.
  5. 무료로 시작 · DX 콘솔의 “AWS Interconnect - multicloud - Free Tier”는 500 Mbps가 미리 선택됩니다. 상대 CSP 쪽 쿼터를 먼저 확인하세요.

last mile

DX 콘솔 › Last mile Interconnect

  1. 준비 · 파트너 가입, 사이트 CPE의 파트너 망 연결, DX Gateway(생성 중에 만들어도 됨).
  2. Create new last mile Interconnect · 파트너(예: Lumen)와 가장 가까운 Interconnect 메트로를 고르면 연결 리전이 표시됩니다.
  3. 속도·ID · 대역폭(1–100 Gbps), DX Gateway, 파트너 계정 ID를 입력합니다.
  4. 수락 · activation key를 파트너 포털에서 입력합니다. 파트너가 먼저 만들었다면 Accept last mile Interconnect에 키를 넣습니다.
  5. 자동 구성 · 연결 4개, BGP·VLAN·ASN, MACsec이 구성되고 DX Gateway에 붙습니다.

공통: Interconnect마다 CloudWatch Network Synthetic Monitor 하나가 추가 비용 없이 붙어 지연과 패킷 손실을 재고, 대역폭 사용률(%) 지표로 경보를 걸 수 있습니다.

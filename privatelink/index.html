AWS PrivateLink · 서비스 단위 사설 연결

필요한 서비스만 사설 IP로 내 VPC에 연결하세요

AWS PrivateLink는 서비스를 내 VPC 안의 사설 IP로 가져옵니다. 인터넷 게이트웨이, NAT, 공인 IP 없이 AWS 서비스, 다른 계정의 서비스, 파트너 SaaS에 접근하고, 접근 가능한 대상을 서비스 단위로 제한합니다.

Why PrivateLink

서비스 하나를 쓰려고 네트워크 전체를 열 필요는 없습니다

VPC 피어링이나 Transit Gateway는 네트워크끼리 경로를 엽니다. PrivateLink는 특정 서비스로 가는 진입점만 내 VPC에 만듭니다. 상대 VPC의 다른 자원에는 경로가 생기지 않습니다.

Private

인터넷 노출 없음

프라이빗 서브넷에서 인터넷 게이트웨이, NAT, 공인 IP 없이 서비스에 접근합니다.

One-way

단방향 연결

소비자 VPC만 연결을 시작할 수 있습니다. 공급자 VPC에서 소비자 VPC로 들어오는 경로는 생기지 않습니다.

Overlap

CIDR 중복 허용

소비자와 공급자가 서로 다른 VPC라면 IP 대역이 겹쳐도 됩니다. 소비자 VPC 안의 ENI로 접근하기 때문입니다.

Provider & consumer

공급자는 서비스를 내놓고, 소비자는 엔드포인트를 만듭니다

PrivateLink 연결은 두 계정의 작업이 만나서 완성됩니다. 공급자는 로드 밸런서 뒤에 서비스를 두고 endpoint service로 공개하며, 소비자는 자기 VPC에 엔드포인트를 만들어 그 서비스에 연결합니다.

Consumer

서비스를 쓰는 쪽

  • subnetAZ마다 서브넷을 골라 Interface endpoint를 만듭니다. AZ마다 ENI가 하나씩 생깁니다.
  • SG엔드포인트 ENI에 보안 그룹을 붙여 접근할 수 있는 클라이언트를 제한합니다.
  • DNSPrivate DNS를 켜면 기존 서비스 이름 그대로 엔드포인트로 접속합니다.
consumer → provider
단방향
Provider

서비스를 내놓는 쪽

  • NLBNetwork Load Balancer 뒤에 서비스를 두고 endpoint service를 만듭니다. 어플라이언스는 Gateway Load Balancer를 씁니다.
  • allow연결을 허용할 AWS 계정이나 IAM 주체를 지정하고, 요청을 수동으로 수락하게 설정할 수 있습니다.
  • region지원 리전을 추가하면 다른 리전의 소비자도 엔드포인트를 만들 수 있습니다.

Features

주요 기능

Cross-Region

리전 간 PrivateLink

다른 리전에 있는 endpoint service와 AWS 서비스에 Interface endpoint로 연결합니다. 리전 DNS 이름만 제공되며, 장애 시 AZ 간 전환은 되지만 리전 간 전환은 하지 않습니다.

Name resolution

Private DNS

공급자가 도메인 이름을 검증해 연결해 두면, 소비자는 애플리케이션 설정을 바꾸지 않고 같은 이름으로 엔드포인트에 접속합니다.

Access control

Endpoint policy

엔드포인트에 리소스 정책을 붙여 이 엔드포인트로 호출할 수 있는 주체와 작업, 리소스를 제한합니다.

Hybrid

온프레미스에서 접근

Direct Connect, Site-to-Site VPN, Transit Gateway, Cloud WAN, VPC 피어링을 거쳐 온 트래픽도 엔드포인트에 도달합니다.

VPC Lattice

Resource endpoint

로드 밸런서 없이 다른 VPC나 온프레미스의 데이터베이스, 도메인 이름, IP 대상에 TCP로 접근합니다. 공급자는 resource gateway로 리소스를 공유합니다.

Inspection

Gateway Load Balancer endpoint

VPC 라우팅 테이블의 next hop으로 지정해 트래픽을 방화벽 같은 가상 어플라이언스 플릿으로 보냅니다.

Endpoint types

PrivateLink 기반 VPC 엔드포인트 유형

연결할 대상에 따라 엔드포인트 유형이 다릅니다. Amazon S3와 DynamoDB용 Gateway endpoint는 PrivateLink를 쓰지 않으므로 여기에 포함하지 않았습니다.

Reference architecture

IP 대역이 겹쳐도 서비스만 연결합니다

소비자 VPC와 공급자 VPC가 같은 10.0.0.0/16을 써도 Interface endpoint로 서비스에 연결됩니다. 온프레미스는 소비자 VPC를 거쳐 엔드포인트에 도달하고, 다른 리전의 소비자는 리전 간 PrivateLink를 씁니다.

Getting started

내 서비스를 PrivateLink로 공개하는 순서

  1. STEP 1

    NLB 준비

    공급자 VPC의 두 개 이상 AZ에 Network Load Balancer와 대상 그룹을 만듭니다.

  2. STEP 2

    Endpoint service 생성

    NLB를 선택해 endpoint service를 만들고, 연결을 허용할 주체를 추가합니다.

  3. STEP 3

    엔드포인트 생성

    소비자는 서비스 이름으로 Interface endpoint를 만들고 서브넷과 보안 그룹을 고릅니다.

  4. STEP 4

    연결 수락

    수락이 필요하도록 설정했다면 공급자가 연결 요청을 수락합니다.

  5. STEP 5

    DNS로 접속 확인

    엔드포인트 DNS 이름이나 Private DNS 이름으로 서비스에 접속해 봅니다.

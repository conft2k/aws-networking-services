CloudFront는 사용자 요청을 지연이 가장 낮은 엣지 로케이션에서 받아 캐시로 응답합니다. 캐시에 없는 요청만 AWS 네트워크를 따라 오리진까지 가고, 오리진은 사설 서브넷이나 비공개 S3 버킷에 둘 수 있습니다.

Why CloudFront

가까운 곳에서 응답할수록 빠르고, 오리진은 덜 일합니다

국내외 사용자에게 같은 품질로 콘텐츠와 API를 전달하려면, 요청을 사용자 가까이에서 끝내고 오리진으로 가는 요청 수를 줄여야 합니다.

Cache

계층형 캐시

POP, regional edge cache, Origin Shield가 차례로 요청을 흡수해 오리진 부하를 줄입니다.

Protect

엣지에서 막는 공격

Shield Standard가 네트워크·전송 계층 DDoS를 막고, AWS WAF가 애플리케이션 계층 요청을 걸러냅니다.

Program

엣지에서 실행하는 코드

CloudFront Functions와 Lambda@Edge로 헤더, URL, 인증 로직을 오리진 앞에서 처리합니다.

Request path

요청이 오리진에 닿기까지

DNS가 사용자를 지연이 가장 낮은 POP으로 보내고, 캐시에 없으면 다음 계층으로 넘어갑니다. PUT, POST, PATCH, OPTIONS, DELETE 같은 프록시 메서드와 동적 요청은 regional edge cache를 거치지 않고 POP에서 오리진으로 바로 갑니다.

Features

주요 기능

S3 origin

Origin Access Control

S3 버킷을 공개하지 않고 CloudFront에서만 읽게 합니다. SSE-KMS 암호화 객체와 PUT·DELETE 요청도 지원하며, 레거시 OAI를 대체하는 권장 방식입니다.

Private origin

VPC origins

사설 서브넷의 ALB, NLB, EC2 인스턴스를 오리진으로 씁니다. CloudFront가 서비스 관리형 ENI로 접근하므로 오리진에 공인 IP가 필요 없습니다. VPC에는 인터넷 게이트웨이가 연결되어 있어야 하며, AWS RAM으로 다른 계정의 VPC origin을 공유받아 쓸 수도 있습니다.

Availability

Origin failover

Primary와 Secondary 오리진을 origin group으로 묶습니다. 지정한 상태 코드나 연결 실패, 타임아웃이 나면 GET, HEAD, OPTIONS 요청을 Secondary로 다시 보냅니다.

Edge security

AWS WAF · Shield

배포에 web ACL을 연결해 L7 요청을 검사합니다. Shield Standard는 별도 요금 없이 모든 배포에 적용되고, Shield Advanced로 확장할 수 있습니다.

Client identity

Viewer mTLS

엣지에서 클라이언트의 X.509 인증서를 trust store로 검증해, 신뢰하지 않는 클라이언트를 애플리케이션 앞에서 차단합니다. Connection Function으로 검증 로직을 더하고 OCSP 폐기 확인, 인증서를 오리진에 넘기는 passthrough 모드도 쓸 수 있습니다. 추가 요금은 없습니다.

Pricing

Flat-rate 요금제

CDN, AWS WAF·DDoS 보호, 봇 관리, Route 53 DNS, CloudWatch Logs 수집, 엣지 컴퓨팅, S3 스토리지 크레딧을 배포 하나 단위의 월 정액으로 묶은 요금제입니다. Free, Pro, Business, Premium 네 등급이 있고 초과 요금이 없습니다.

Edge compute

CloudFront Functions와 Lambda@Edge

헤더 조작, URL 재작성, 토큰 검사처럼 가볍고 짧은 로직은 CloudFront Functions에, 네트워크 호출이나 요청 본문 처리가 필요한 로직은 Lambda@Edge에 둡니다.

Reference architecture

공개 진입점은 CloudFront 하나로

동적 요청은 VPC origin으로 사설 서브넷의 ALB에, 정적 파일은 OAC로 보호한 S3에 보냅니다. ALB를 Primary로 둔 origin group에 S3 정적 페이지를 Secondary로 묶어 장애 시 응답을 유지합니다.

Getting started

배포를 여는 순서

  1. STEP 1

    오리진 준비

    S3 버킷이나 사설 서브넷의 ALB를 준비합니다. 둘 다 공개하지 않아도 됩니다.

  2. STEP 2

    배포 생성

    오리진을 등록하고 S3에는 OAC를, ALB에는 VPC origin을 연결합니다.

  3. STEP 3

    캐시 동작 설정

    경로 패턴별로 캐시 정책, 오리진 요청 정책, 허용 메서드를 정합니다.

  4. STEP 4

    도메인 · 인증서

    대체 도메인 이름을 추가하고 us-east-1의 ACM 인증서를 연결합니다.

  5. STEP 5

    DNS 연결

    Route 53에서 배포를 가리키는 alias 레코드를 만들고 응답 헤더로 캐시 동작을 확인합니다.

Pricing
